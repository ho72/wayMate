처음 읽는 팀원은 01번으로 서비스·일정 용어를 이해한 뒤 02번의 대사를 따라가면 됩니다. 화면을 제작할 때는 03번, 데이터·연동을 구현할 때는 04번, 작업 배정·완료 판단에는 05번을 참조합니다. 문서의 ‘필수’는 제작자가 구현할 범위이며 사용자가 모든 콘텐츠를 이용해야 한다는 뜻이 아닙니다.

개발을 나눌 때는 06번의 책임·파일 경계를 보고 05번과 실제 작업 이슈에 이름·가용 시간을 기록합니다. 전체 팀은 5명으로 확인됐고, 개발 인원·역량·기획서 제출 형식·기한은 아직 미정입니다.

화면을 눈으로 검토할 때는 08번의 [전체 PDF](wireframes/v1/waymate-screen-spec-v0.1.pdf)를 봅니다. 피드백은 `WF-019 / 요소 4 / 변경안`처럼 남깁니다. 기존 기본 범위 B와 이번 요청의 개인 장소·일정 연동 확장 E, 기존 추가 O를 구분했으며 E는 구현 전 계약 갱신이 필요합니다. 목표 화면과 현재 구현 상태는 각각 08번과 07번으로 구분합니다.

## 작성 기준

- 프로젝트 개발 가제는 `wayMate`로 통일합니다. 최종 서비스명은 별도로 결정합니다.
- 기능 ID `DM01`~`DM11`은 후속 문서에서도 동일하게 사용합니다.
- 서비스 목표, 목업의 실제 동작, 대본·시연 데이터에 의한 재현을 구분합니다.
- 후속 문서에서 제작 범위를 바꾸면 01번 문서와 관련 검수 항목도 함께 갱신합니다.
- 작성 예정 문서는 실제 파일이 생긴 뒤 링크를 추가합니다.

## v0.5 종합 검토 반영

2026년 11월 11일 종합 검토의 개발 계약 두 건과 B의 사전 경험을 보완하고 서비스 가설·실현성 검증을 분리했습니다. 아래는 구현할 기준이며 기능·사용자·실제 SDK 검수를 통과했다는 기록이 아닙니다. 기존 담당자·마감은 미정으로 유지했고 새 V의 담당자·마감도 미정, 결과는 미실시입니다.

| 항목 | 반영 기준 | 관련 문서 |
|---|---|---|
| 모의 내비의 명령·결과 | NAV_MOCK_RESULT로 현재 모의 add/remove 결과 지정. source=real/mock과 outcome 분리, 실패·unknown·재시도·취소/초기화의 늦은 결과와 실제 증빙 경계 명시 | 01~05 |
| 최초 최종 선택 | MEETING_END 때 최초 finalId·round=1·requestId=null 생성. A together 때만 B 요청 발급. 대기 중 연결 종료는 B 요청 정리 후 내 친구 선택만 제공, 재시연도 A부터 시작 | 01~05 |
| B의 사전 경험 | B도 승인된 A 소개를 확인하고 A 캐릭터 소개를 들었다는 기본 이야기 명시. 생략/누락·현재 공개 제외 시 일반 인사, 실제 B 열람 증빙과 구분 | 01~05 |
| 시간 부담의 표시 | 추가 주행 외 본인 대기·첫 만남·선택적 산책을 함께 표시. 순수 추가 부담·실시간 계산으로 단정하지 않음 | 01~05 |
| 별도 가설 검증 | 05번 6.4절에 V01 방문 캐릭터 효과·V02 내 친구 가치·V03 늦은 응답·V04 전체 시간 부담·V05 주행 실현성. 기능 검수 Q와 별도 관리 | 01~05 |

## v0.3 통합 검토 반영

2026년 11월 11일 01~05번의 범위·대사·화면·API·검수 연결을 검토해 아래 기준을 맞췄습니다. 구현·SDK·실제 사용자 검수의 통과 기록을 추가한 것은 아닙니다. 담당자·검토자·가용 시간·마감은 미정으로 유지합니다.

| 항목 | 확인한 충돌·모호함과 수정 기준 | 반영 문서 |
|---|---|---|
| 공개와 본인 여행 | 소개 승인·여행 요약 공유·저장을 분리. 선택 취향 미공개는 지원 외 입력으로 처리하지 않으며 본인 모드 유지 | 01~05 |
| 조건별 대사 | 고정 대사의 비공개 취향·차분한 표현·선행 대화 가정 문제 수정. 중립/일정 중심/일반 인사와 cue 선행·대체 대사 명시 | 01~05 |
| 회차의 연결 범위 | 종료 후 새 연결·편집 가능 시점 명확화. 한 회차 한 연결 요청, 새 연결은 전체 초기화·공개 철회는 별도 처리 | 01~05 |
| 전달·상태 복원 | 공개/연결 버전·중복 ACK 정의. 재불러오기 때문에 진행 중 만남·결말이 첫 소개로 돌아가지 않음 | 01·03~05 |
| 버튼과 RPC | 의미 ID와 명령의 actionBindings, target/payload, 요청 모드·최종 동시 선택의 terminal 규칙 명시 | 02~05 |

| 최종 재시연 | 만남 종료 후 checkpoint로 통일. 서버의 final_replay 제한, 현재 내비·제한·복구 기록 보존, 새 사회적 요청 차단 | 01~05 |
