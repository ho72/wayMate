# 모바일·백엔드·Pleos 통합 시연 운영표

2026-11-15 작업본 기준. 모바일에서 확인한 **같은 계정·저장 여행·회차·전달본**을 차량이 받고, 만남과 두 결말까지 이어가는 경로다. 기존 3000 차량 시연과 3004 개인 서비스의 데이터는 별도로 유지한다. main 병합·공개 배포를 의미하지 않는다.

## 실행 기준

저장소의 `service/`에서 Node 22.22.2로 실행한다.

```sh
npm ci --ignore-scripts
npm --prefix ../mock-app ci --ignore-scripts
npm run start:scenario
```

- 모바일: <http://127.0.0.1:3008/#trips>
- 진행자: 같은 브라우저 계정으로 <http://127.0.0.1:3008/scenario-operator>
- 기본 DB: `service/runtime/scenario-integrated.sqlite`.
- 계정·여행별 v4 상태와 선택한 전달본: 위 DB 경로의 `.journeys/` 폴더.
- 차량의 공통 시연 API와 개인 계정 API를 모두 3008로 빌드한다. 에뮬레이터에서는 `10.0.2.2:3008`에 접속한다.

일반 `.env`의 3004 설정과 섞이지 않도록 전용 실행기는 `SERVICE_SCENARIO_PORT`(기본 3008), `SERVICE_SCENARIO_DB_PATH`를 사용한다. 포트를 바꾸면 APK의 두 포트도 함께 바꾼다. OpenAI 키는 기존 서버 설정을 사용하며 클라이언트로 보내지 않는다.

```sh
cd mock-app/vehicle
./gradlew :app:assembleMockDebug :app:assembleRealDebug \
  -PwaymateApiPort=3008 -PwaymatePersonalApiPort=3008
adb install --user 10 -r app/build/outputs/apk/mock/debug/app-mock-debug.apk
adb shell am start --user 10 -n com.waymate.app.mock/com.waymate.app.MainActivity
```

`--user 10`은 이번 Pleos 에뮬레이터의 활성 사용자다. 다른 기기는 `adb shell am get-current-user`로 확인한다. `-r`로 기존 앱 데이터를 유지한다.

## 대표 시나리오

12월 14일 강릉, 13:00–15:00 가능 시간으로 시연한다. 만남은 14:15–14:35, 함께 선택한 뒤 산책은 14:35–14:55다. 고정 후보·장소·이동 수치를 사용하는 시연이며 실시간 매칭·장소 검색을 의미하지 않는다.

| 단계 | 사용자 동작 | 진행자 동작·확인 |
|---|---|---|
| S01–S02 | 가입·친구 선택·대화로 여행 계획 → 초안 확인/수정 → 저장. 내 여행에서 해당 카드의 지도·일정 상세 열기 | 저장한 여행 제목·날짜·장소 확인. 상세에서 친구 찾기 진입 |
| S03 | 나를 소개하는 말 직접 작성 → 가능한 날짜·시간 확인 → 소개 공개와 여행 요약 공유를 각각 확인 → 루밋 소개 보기 | 계정 별명·선택 캐릭터를 재사용. 입력하지 않은 사진/성격 취향을 만들지 않음 |
| S04 | 연결 요청 → 상대 수락 확인 → 공통 시간 최종 확인 → Pleos로 이어가기 | 진행자 창에서 **같은 여행** 선택 → 연결 요청 수락. 수락만으로 연결 확정하지 않음 |
| S05 | 정차한 Pleos에서 **웹에서 준비한 여행 불러오기** | 모바일이 **차량 수신 확인 완료**로 바뀌는지 확인. 그전에는 전달 준비 상태 |
| S06–S07 | 대화 고르기 → 상대 캐릭터와 알아가기 → 질문. 에이전트로 말 전하기 → 문장 확인·전송 → 답장·후속 답변 확인 | 메시지 요청의 준비된 답장 보내기. 캐릭터 답변과 상대 응답을 구분 |
| S08 | 둘이 직접 통화하기 → 동의·제안 → 종료 | 통화 요청 수락. 실제 실시간 통화가 아닌 준비 샘플 |
| S09 | 만남 제안 받기 → 같은 장소·시간 확인·제안 | 해당 만남 제안 수락 |
| S10 | 만남 카페 경유지 확인 → **모의 경유지 추가 승인** → 확인 | 진행자 창의 **모의 반영 확인** → **만남 시작으로 이동** → 재연 확인 → **만남 종료 · 선택 열기** |
| S11–S12 | 함께 여행 이어가기 → 선택 제출·확인 | **상대도 함께 여행**. 양쪽 제출 후 함께 결말 확인 |
| 다른 결말 | 진행자가 새 최종 선택 회차를 연 뒤 내 캐릭터와 여행 이어가기 → 선택 제출·확인 | **다른 결말 다시 시연** → **상대는 각자 여행**. 이전 결과가 남지 않고 내 친구 결말로 전환 |

결말 재시연은 내비 추가를 반복하지 않는다. 진행자 버튼은 서버의 현재 요청·회차·행동 조건이 열릴 때만 표시된다. 진행자가 차량의 승인·사용자 선택을 대신 실행하지 않는다.

## 다시 처음부터

모바일의 해당 여행 진행자 화면 `/#journey-operator/<tripId>`에서 **새 촬영 회차 준비**를 누른다. 차량을 받기 전이면 모바일의 정리 확인으로 끝낸다. 차량을 받았다면 Pleos의 정리 화면에서 필요한 경유지 제거를 별도 승인하고, 진행자에서 제거의 **모의 반영 확인**, 차량에서 정리 확인을 마친다. 처리 중·결과 미확인·동일 기기 ACK가 남으면 다음 회차를 열지 않는다. 상태 파일·앱 데이터·내비 journal을 삭제해서 재시연하지 않는다.

## 이번 통합 변경

- 저장 여행별 v4 상태·공개 소개·선택한 전달본을 모바일과 Pleos가 공유한다.
- 계정 여행 게이트웨이에 `/api/agent/dialogue`를 연결했다. 회차별 파일 캐시·생성 중복 방지·유료 호출 상한·정차 조건을 기존 차량 대화 서비스와 공유한다.
- 진행자에게 현재 여행의 만남 시작/종료, 모의 내비 결과, 양쪽 최종 선택, 다른 결말 재시연을 연결했다. 일반 계정 서비스에서는 시연 진행 API가 열리지 않는다.
- 두루·루밋·모카를 전달 계약과 차량 대화 캐릭터에 일관되게 매핑한다.
- 서비스 CI가 가져오는 공통 차량 서버 의존성도 설치하고 해당 경로 변경 시 검사하도록 보완했다.

## 검수 근거와 한계

- Node 22.22.2: 서비스 전체 110개, 공통 차량 서버 350개 통과.
- `service/tests/scenario-flow.test.mjs`: 세 캐릭터 각각 저장 여행 → 전달·ACK → 대화·음성 API → 메시지·통화 → 모의 내비·만남 → 두 결말 → 재시작·캐시 재사용 → 경유지 제거·정리를 실제 HTTP로 연속 검사했다. 생성·음성 제공자는 테스트 대체 구현이며 외부 과금은 없다.
- Mock·Real APK, JVM 단위 테스트, 양쪽 Lint 통과. Real APK 빌드 성공과 실제 NaviHelper 경로 변경 성공은 구분한다.
- 실제 브라우저에서 지도 상세 → 직접 소개 작성 → 공개 확인 → 추천 → 연결 요청 → 별도 진행자 수락 → 공통 시간 확인 → 차량 전달 준비까지 수행했다.
- 실제 Pleos 연속 검사 결과·화면·APK·로그는 `output/scenario-integration-20261115/`에 보관한다. 최종 결과는 그 폴더의 `verification.json`을 따른다.

이번 기기 검수는 실제 정차 상태와 모의 내비를 사용한다. 마이크/STT·실시간 상대 통화·실차·새 OpenAI/ElevenLabs 생성 성공은 이번 통합 검사로 증명하지 않는다. 기본 준비 음원·자막으로 시연할 수 있고, 유료 생성은 설정과 별도 동의가 있을 때 기존 서버 경로를 사용한다.

빠른 연속 검사는 `service/`에서 `npm run test:scenario`로 재현한다. 기기 검사는 `MobileScenarioIntegrationDeviceTest`를 3008 APK·전용 서버·검수 계정에서 실행한다. 진행자 세션은 로그·문서에 기록하지 않는다.
