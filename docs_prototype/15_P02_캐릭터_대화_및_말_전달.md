# P02 캐릭터 대화와 말 전달

2026-11-12. 기준은 02번 S06·S07, 03번 §5.3~5.5, 04번 콘텐츠·메시지 계약과 05번 DM06/Q04/Q23이다. O01 안전한 초기화 구현 위에 연결하며 `docs_proposal`은 수정하지 않는다.

## 구현한 흐름

차량에서 connected 여행을 불러온 뒤 **대화 고르기 → 콘텐츠 고르기**로 진입한다. 상대 소개는 ‘솔바람의 에이전트’로 표시하고 공개 프로필 기반 답변·사용자 메시지·기기 낭독의 출처를 구분한다. 미구현 통화·게임 버튼은 제공하지 않는다. 만남 제안은 대화를 끝내지 않아도 선택할 수 있다.

| 기능 | 동작 |
|---|---|
| 상대 캐릭터와 알아가기 | Q1·Q2 선택 후 물어보기. 공개 근거를 만족할 때만 준비된 대본 답변. B 메시지 요청/이벤트 없음 |
| 모르는 소개 | 공개 필드가 없으면 모름 안내. 직접 물어보기는 M1/M2 보낼 말 확인 화면으로만 이동하며 전송하지 않음 |
| 말 전달 | M1/M2 선택 → 보낼 문장 확인 → 별도 전송 확인. 시연 서버 저장 후 현재 thread/request로 B 답장 대기 |
| B 답장 | `/operator`에서 현재 메시지의 **B 메시지 답변**. 해당 M1/M2 대본 답장과 F1 후속 질문만 저장 |
| 답장 확인 | 목록/홈에 새 답장 표시. 화면 전환·자동 낭독 없이 사용자가 직접 열어 확인. 읽음은 차량의 회차별 로컬 UI 기록 |
| 후속 답변 | 실제 F1 발생 후 R1/R2 선택·확인 전송. 한 번만 저장하고 내 에이전트의 정리 문장 표시. 만남·통화 동의는 만들지 않음 |
| 내 친구·휴식 | 콘텐츠 목록에서 내 친구 또는 쉬기. 본인 계획·다음 일정·복귀 정보를 유지하며 자동 재생/요청 없이 복귀 |
| 종료·미확인 | 연결 종료·만남 취소/거절은 대기 메시지를 닫음. 늦은 B 응답으로 되살리지 않음. 미확인 전송은 기존 ID/영수증 확인 우선 |

같은 대기/후속 질문이 남아 있으면 새 메시지를 만들지 않는다. 이미 전송된 메시지는 취소로 회수하지 않으며, 도착 전 미확인 `MESSAGE_SEND`는 원래 commandId를 지정해 실행을 막을 수 있다. `MESSAGE_REPLY` 결과 미확인은 같은 요청의 영수증/재전송으로 확인한다. 성공 이전에 전달 완료로 표시하지 않는다.

웹 준비·차량 수신·본인 여행은 기존 경계를 유지한다. my_trip에는 상대 문답/메시지를 제공하지 않으며 내 친구와 일정만 표시한다. 현재 연결·차량 활성/정차·추가 제한·내비 미확정 상태를 서버에서 다시 검증한다. 제한/미확인 상태에서는 긴 문답을 숨기고 짧은 잠금 안내만 표시한다. 주행 음성 권한을 새로 열지 않는다.

## 공개 근거와 계약

`shared/config/content-v4.mjs`가 Q1/Q2, M1/M2, F1, R1/R2의 준비 대본을 관리한다. B fixture에는 확인된 공개 필드와 표현 프리셋을 명시했다. 캐릭터가 현재 B의 감정·의사를 추정하지 않는다. Q2의 ‘둘 다’는 A도 바다 산책/카페 관심사를 명시적으로 공개한 경우에만 사용한다. A 본인에게 보이는 비공개 관심사만으로 공통 취향 대사를 만들지 않는다.

v4 계약에 선택적 `content` 저장/차량 projection, `MESSAGE_SEND`, `MESSAGE_REPLY`, `B_RESPONSE(kind=message, decision=reply)`와 메시지 취소 표식을 추가했다. threadId/requestId/connectionId, 발생한 후속 질문을 현재 대상으로 검증한다. 자유 B 답변은 받지 않는다. 차량만 실제 메시지 내용을 받고 웹·O01에는 content=null, O01에는 현재 응답 대상 ID만 제공한다.

기존 v4 저장 파일에 content가 없어도 읽을 수 있다. v2/v3는 변경하지 않는다. 재접속·중복 요청은 같은 메시지를 복원하며 새 요청을 자동 생성하지 않는다. 전체 초기화 완료는 메시지를 비우고, 이전 회차의 B 응답은 새 회차를 바꾸지 못한다. 메시지를 SDK 감사 보존 기록에 복사하지 않는다.

## 낭독·캐릭터 공통 기반과 경계

`AgentSpeech`는 로컬 Android TTS를 이용하는 선택적 문장 낭독 기반이다. 실제 재생 시작 콜백 후에만 ‘말하는 중’으로 표시하고, 오디오 포커스 거절/상실·앱 가림·화면 이동·제한·초기화에서 중단한다. 이전 발화의 늦은 콜백은 토큰으로 무효화하며 포커스 복귀나 재진입으로 자동 재개하지 않는다. 마이크나 실제 상대 음성 통신은 사용하지 않는다.

이번 Pleos 에뮬레이터에는 `ai.pleos.playground.caas/.service.speech.SpeechService`가 TTS 서비스로 등록돼 있다. 다만 기본 TTS 엔진 설정은 null이며 앱 로그는 `not bound to TTS engine`이다. 앱의 낭독 준비 실패·비활성 낭독 버튼·자막 대체를 실제 확인했다. 서비스 등록을 실제 낭독 성공으로 간주하지 않으며 엔진 바인딩/설정 원인 확인은 후속이다. **낭독 성공·실제 오디오 포커스 경합·실제 주행 음성은 미검증**이다. 콜백 정책은 JVM 회귀 테스트와 양쪽 APK 컴파일로 검증했다. TTS 엔진/언어를 임의 설치하거나 성공으로 대신 기록하지 않는다.

기존 파란 드래곤 PNG와 B의 임시 캐릭터 그림을 사용한다. 이번 범위는 발화 상태/자막/중단을 연결할 기반이며, 3D 모델·눈 깜빡임·입 모양 애니메이션을 완성한 것은 아니다. 해당 소재 교체는 업무 RPC와 분리돼 있다.

## 검증 기록

Pleos Connect 2.1/API34 사용자 10의 실제 real 앱과 O01 브라우저에서 확인했다. O01 후 비어 있던 회차 3에 모바일 프로필·매칭·전달만 API fixture로 준비했다. 차량 불러오기와 모든 P02 선택/확인/전송, B 답장 지정은 실제 UI에서 실행했다.

1. Q1 공개 답변 뒤 messages=[]·B 대기 요청 없음. Q2는 A 관심사 미공개로 모름 안내이며 직접 물어보기 뒤에도 전송 없음. 공개 근거가 충분한 Q2는 별도 자동 테스트에서 대본을 확인했다.
2. M1 명시 전송 → 목록으로 이동 → O01 답장. 목록과 ‘새 답장’ 표시를 유지하고 직접 열어 확인 → R1 전송 완료. 만남 상태 none 유지.
3. M2 전송 대기 중 앱 강제 종료/재시작. 같은 thread/request 복원 → O01 답장 → R2 전송 완료. 이전 M1도 그대로 유지.
4. 추가 시연 제한에서 canInteract=false·새 메시지 binding 없음. 해제 후 내 친구·계획으로 복귀. 실제 주행 제한 전환 시험으로 기록하지 않는다.
5. 최종 APK 데이터 보존 재설치 후 두 대화와 내 친구 홈 복원. 전후 SDK journal 바이트 동일, 새로운 실제 내비 호출 0회.
