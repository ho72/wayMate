# 캐릭터 중심 주행·정차 모드

2026-11-13. 사용자 요청에 따라 큰 캐릭터를 유지하면서 정차 상세 화면과 주행 간편 화면을 분리했다. 공식 [DO 선언](https://source.android.com/docs/automotive/driver_distraction/guidelines), [기능별 UXR 처리](https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/driving-restriction-development-guide), [시선 분산 최소화](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline)를 기준으로 구현한다. 이 결과는 에뮬레이터 개발 검증이며 배포 심사·실차 V05·STT/자유 대화 지원 판정과 구분한다.

## 화면과 기능

| 상태 | 표시·허용 | 계속 잠기는 기능 |
|---|---|---|
| parked | 채택 렌더 캐릭터의 대기/발화 동작, 기존 홈·일정·콘텐츠·통화·만남·내비·결말 | 기존 동의·역할·신선도·복구 조건은 그대로 적용 |
| driving_limited | 오른쪽 앱 창의 큰 정적 캐릭터, 다음 일정 시각 또는 짧은 상태 한 줄, `친구 한마디 듣기`·`음성 멈추기` | 스크롤·키보드·상세 목록·새 메시지/통화·만남 동의·내비 승인·최종 선택 |
| blocked | 큰 정적 캐릭터·최소 상태·음성 중단 | 미확인·미검증 제한 프로필·비활성·만료·초기화/복구 중 새 재생과 업무 조작 |

주행 중 캐릭터는 대기 바운스·회전·발화 모션을 모두 끈다. 음원이 재생돼도 정적이다. 두 버튼과 최소 64dp 높이는 이 앱의 설계 선택이며 공식 허용 개수나 승인 규격으로 주장하지 않는다. 계기판 / 순정 내비 / wayMate 3분할을 대표 배치로 유지한다.

현재 음성은 준비 합성 음원 한마디다. 사용자가 직접 선택해야 시작하며 실제 마이크·음성 인식·생성형 문답·실시간 상대 통신을 제공하는 표시를 넣지 않는다. 04번의 후속 `driving_voice`와 구분한다. 준비 음원은 1개를 추가해 총 35개다.

## 전환·서버·외부 효과

- MainActivity에 `distractionOptimized=true`를 선언했다. 최초 차량 상태가 미확인이면 상세 화면을 먼저 보여주지 않는다. 모든 정차 상세 화면보다 제한 모드 분기를 먼저 적용한다.
- 실제 `CarUxRestrictionsManager`의 현재값과 변경 콜백을 사용한다. 기어·속도 숫자로 앱이 정차를 추정하지 않는다. 현재 확인한 DO=true·activeRestrictions=0 또는 0x50 프로필만 주행 간편 모드로 처리한다. 더 강한/새 플래그나 모순된 관측은 blocked다.
- `CAR_STATUS`에 raw `uxRestrictions`를 추가하고, 서버가 restricted와의 모순을 거부한다. 과거 저장/클라이언트 호환을 위해 optional이나, raw 없는 restricted=true는 주행 간편 음성을 허용하지 않는다. raw 제한 변경은 업무 버전에도 반영한다.
- 서버는 기존 정차 업무 권한을 유지한다. 주행 모드 자체가 새 업무 RPC를 만들지 않는다. 초기화·복구·시연 제한·foreground/상태 만료는 준비 음성도 잠근다.
- 음성 유효 시간은 서버의 남은 fresh 기간에서 HTTP 왕복·저장 지연을 보수적으로 차감한다. 새 응답 없이 화면 재구성으로 기간을 연장하지 않는다. 만료 시 재생을 중단하고 버튼을 비활성화한다. 갱신으로 자동 재생하지 않는다.
- 모드/제한 변경 시 이전 음성·미전송 승인 intent/grant와 확인창을 정리한다. 제한 사실을 서버에 먼저 보고한 뒤 미확인 승인 결과를 조회한다. 이미 발생한 SDK 사실 보고는 버리지 않는다.
- P 복귀·창/오디오 포커스 복귀만으로 대사·통화·동의·내비 변경을 실행하지 않는다. 현재 상태를 확인하고 사용자가 다시 선택해야 한다.

DO 자기 선언은 앱 심사 승인이 아니다. 라이프스타일이라는 사용자 설명은 서비스 분류 확인의 참고로 남기며 특정 지역/양산차의 주행 허용을 대신 확정하지 않는다. 순정 내비 지도 배경은 계속 보류한다.

## 검수 기록

서버 **272개**·JVM **43개**, 기기 **14개(실제 전환 1·SDK 상태 4·모의 음성/화면 9)**가 통과했다. 실제/모의 앱·양쪽 기기 테스트 APK 빌드와 Lint 오류 0을 확인했다. Lint 경고는 real/mock 각각 26/26개다. 기존 23·25번의 서로 다른 시점 검증 수를 재실행 수로 합산하지 않는다.

실제 전환 검수는 production MainActivity와 실제 서버·NaviHelper·차량 제한 리스너를 사용한다. 공식 Virtual Console의 기어/속도 제어와 같은 HTTP 경로를 이용해 P/0→D/36km/h→P/0을 넣고 실제 UXR·화면·재생 결과를 대조한다. 규제 off·강제 허용 목록·지역/속성 변경으로 화면을 열지 않는다.

초기 검수에서는 Console 활성 세션이 없어 DDS bridge가 비활성(503)이거나, 로컬 정차 화면이 먼저 표시되고 서버 확인 버튼은 아직 잠긴 상태를 확인했다. Console UI가 쓰는 세션 heartbeat를 검수 도구가 유지하고 DDS 준비·fresh 버튼을 기다리도록 수정했다. 실제 화면은 공식 3손가락 이동으로 오른쪽 portrait 창에 배치한다. 테스트 종료는 P/속도0·페달0으로 복원하고 해당 Console 세션을 닫는다.

이 전환 검사에는 경유지 변경 호출이 없으며 실제 SDK journal의 전후 바이트/해시를 대조한다. 초기화나 새 여행 ACK를 만들어 성공을 꾸미지 않는다.

## 반복 실행

현재 Pleos ARM 2.1.0/API34, 기본 포트 3000의 서버/실제 앱, 기존 실행 기록이 정리된 기기에서 수행한다. Console 포트는 [공식 셋업](https://document.pleos.ai/docs/connect/guide/getting-started/application-development/use-vehicle-emulator)의 8088을 포워딩한다. 이 기기는 hmg_car_service 명령이 없으므로 해당 규제 on/off를 사용하지 않는다.

```sh
adb -s emulator-5554 forward tcp:8088 tcp:8088
cd mock-app/vehicle
./gradlew :app:assembleRealDebug :app:assembleRealDebugAndroidTest :app:assembleMockDebugAndroidTest
adb -s emulator-5554 install --user 10 -r app/build/outputs/apk/real/debug/app-real-debug.apk
adb -s emulator-5554 install --user 10 -r -t app/build/outputs/apk/androidTest/real/debug/app-real-debug-androidTest.apk
adb -s emulator-5554 shell am instrument --user 10 -w -e class com.waymate.app.platform.DrivingModeTransitionDeviceTest com.waymate.app.real.test/androidx.test.runner.AndroidJUnitRunner
```

`DrivingSurfaceTest`는 서버/SDK 없는 모의 호스트에서 승인창 폐기·수동 재생·상태 만료·갱신 후 무재생을 검사한다. `DrivingModePolicyTest`와 `v4-driving-mode.test.mjs`는 미검증 마스크·raw 위장·만료·동일 boolean의 제한 변경·정차 복귀 시 오래된 명령을 검증한다. instrumentation은 대상 프로세스를 다시 시작하므로 활성 SDK 실행이나 통화 중에는 시작하지 않는다.

## PR #8·#9 리뷰 반영 (2026-11-13)

#8의 SDK 검수 표현을 명시적 `stop()` 후 unknown 통지로 한정했다. 서비스 연결 콜백 `ready=false`를 강제로 재현했다는 주장은 하지 않는다.

#9는 서로 다른 volatile 필드에 쓰던 restricted/raw 관측을 불변 `RestrictionSnapshot` 하나로 바꿨다. CAR_STATUS는 그 참조를 한 번 읽어 known·restricted·raw를 함께 구성하므로 정차·주행·unknown 전환 중 서로 다른 관측이 섞이지 않는다. 캡처한 관측 보존과 동시 발행 회귀 2개를 추가했다.

허용 마스크는 `mock-app/shared/config/driving-policy.json`으로 통합했다. 서버가 직접 읽고 차량 빌드가 Kotlin `DrivingProfiles`를 생성한다. 생성 정책과 JSON의 일치·모드 판정 회귀를 JVM/서버에 각각 추가했다. 계약 JSON 전체를 다시 포맷하지 않았다.

재검증은 #8 서버 264개, #9 서버 273개·JVM 46개·기기 14개(실제 전환/SDK 5·모의 화면/음성 9) 통과다. 실제/모의 앱과 기기 테스트 APK 빌드, Lint 오류 0·경고 각 26개를 확인했다. 실제 Console P/0→D/36→P/0 전환 후 기존 내비 journal 16개의 바이트/해시가 같았다. 초기 모의 테스트 실행은 클래스 패키지 경로 오기로 로드에 실패했으며, 올바른 경로로 재실행한 9개 통과를 최종 결과로 사용한다.
