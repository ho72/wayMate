# v3 여행 준비·차량 홈 및 실제 내비 시험

> 최신 목표(v0.8)는 **탑승 전 모바일 추천·매칭 → Pleos 이동 경험**이며 [04 개발 명세](04_개발_및_연동_명세서.md)의 schemaVersion 4를 따른다. 이 문서의 당시 실행/검증 기록·v2/v3 계약은 보존한다. 이전 P06/P07 차량 매칭 방향을 새 목표로 적용하거나 이 기록을 모바일 매칭 완료 증빙으로 사용하지 않는다.

2026-11-11 · v0.1 · 첫 구현 범위 `preparation-v3` / schemaVersion 3

> 이 문서는 첫 구현·내비 첫 시험 당시 기록입니다. 이후 좌표 호환 처리와 실제 경유지 추가/제거·D 유지가 통과한 최신 결과는 [11 실제 내비 검증](11_실제_내비_좌표_및_경유지_검증.md)을 따릅니다. 아래 첫 unknown/미실시 및 당시 증거는 보존합니다.

## 1. 현재 실행 범위

[09 실행 계획](09_캐릭터_기준_및_개발_실행_계획.md)의 첫 묶음입니다. 01~05·08의 전체 v3 여정 구현과 구분합니다.

| 영역 | 이번 구현 |

| M01 | 한 질문씩 자유 입력·예시 초안·원문 저장·답변 수정·별도 소개값 확인·별명/외형 |
| 준비된 후속 질문 | `interests` 답변이 정확히 `맛집 탐방을 좋아해`이면 `food_detail` 한 차례. 임의 의미 분석·LLM 생성 없음 |
| M02 | 문서의 강릉 고정 계획 확인·별도 저장·prepared_trip 준비 |
| P01 | 웹 준비 불러오기/ACK, 확인한 저장 준비로 직접 시작, 준비가 전혀 없을 때만 기본 시연값 확인 후 시작 |

| 복원 | 같은 deviceId의 새 세션·서버 재시작 후 최신 제한 보고로 활성 여정 복원. 재시작 명령/새 ACK 없음 |

추천·공개 승인·매칭·B 응답·콘텐츠·만남·두 결말·O01·업무 초기화·주행 음성은 아직 없습니다. `capabilities.navigation=false`, `connected=false`, `operator=false`입니다. 공개/관계 전체 명령을 지원하는 schema가 아닙니다. 동행 추천 버튼은 ‘준비 중’으로 비활성입니다. 전체 Q28은 미완료입니다.

## 2. 실행

Node **22.22.2**로 저장소의 `mock-app/`에서 실행합니다.

```sh
npm ci --ignore-scripts
npm start
```

[여행 준비](http://127.0.0.1:3000)에서 질문별 전송 → 별명/외형/소개값 확인 저장 → 고정 여행 계획 저장 → 차량에 전달 준비 순서로 진행합니다. 예시는 자동 전송하지 않습니다. 소개 체크박스와 말투는 기본 미선택입니다. ‘소개값 사용 안 함’ 뒤 확인하면 빈 배열/null로 계속합니다.

서버는 `127.0.0.1:3000`, 차량은 에뮬레이터의 `http://10.0.2.2:3000`을 사용합니다. 역할 헤더는 로컬 시연용이며 인증·공개 배포는 지원하지 않습니다. 최초 준비 브라우저의 localStorage clientId를 유지합니다.

차량은 [vehicle 안내](../mock-app/vehicle/README.md)에 따라 `mockDebug`를 실행합니다. 현재 Pleos 사용자는 10이며 다른 환경에서는 `adb shell am get-current-user`로 확인합니다.

```sh
cd mock-app/vehicle
./gradlew :app:assembleMockDebug :app:lintMockDebug
adb -s emulator-5554 install -r app/build/outputs/apk/mock/debug/app-mock-debug.apk
adb -s emulator-5554 shell am start --user 10 -n com.waymate.app.mock/com.waymate.app.MainActivity
```

‘웹에서 준비한 여행 불러오기’는 서버에 정확한 prepared_trip ACK가 저장된 후 홈을 표시합니다. ‘저장된 준비 확인하고 시작’은 확인 대화상자의 profile/trip 버전으로 CAR_START_TRIP을 전송합니다. 확인 도중 서버 준비가 바뀌면 최신 준비로 몰래 바꾸지 않고 거절합니다. 준비가 일부라도 있으면 기본값으로 덮어쓰지 않습니다.

시작 뒤 웹 준비 변경을 서버에서도 차단합니다. 웹의 전달 수신 확인은 CAR_LOADED에만 해당하며 직접 시작에는 가짜 ACK가 없습니다. 조회/앱 재시작은 새 활성화나 ACK를 만들지 않습니다.

## 3. v3 계약·보존 정책

현재 [JSON Schema](../mock-app/shared/contracts/handoff-v3.schema.json)와 [v3 예제](../mock-app/shared/examples/v3/index.json)를 서버·웹·차량이 함께 사용합니다. 문서 버전과 schemaVersion은 별개입니다.

| 항목 | 현재 규칙 |
|---|---|
| ONBOARDING_ANSWER | `{questionId, answerText, inputSource}`. raw 1~500 Unicode 코드 포인트, trim은 빈 내용 검사에만 사용 |
| 원문 저장 | `onboarding[questionId]={answerText,inputSource,confirmed,revision}`. 공백·줄바꿈·이모지·ㅋㅋ 보존. web owner/server만 제공 |
| 답변 수정 | 뒤 질문/옛 분기 답변·프로필 확인·공개 승인·handoff/ACK 무효화. 저장 계획은 보존하되 프로필 재확인 필요 |
| PROFILE_CONFIRM | `{alias,avatarId,confirmedSummary}`. 별명 NFC/trim 후 1~10자·줄바꿈 불가. 원문에서 enum을 추정하지 않음 |
| 확인 소개 | `interests`, `activityPreference`, `pace`, `conversationStyle`, `speakingStyle`, `expressionPresetIds`, `summarySource:user_confirmed_demo`. 미확인은 빈 배열/null |
| 프로필 | `{version,alias,avatarId,privateSummary,confirmed}`. car의 profile 필드는 null이고 안전한 owner DTO만 preparation/handoff에 포함 |
| prepared_trip | owner/ownerTrip·peer=null·sourceVersions는 `{profile,trip}`만. publication/connection 버전 제외 |
| 공개 상태 | publicApproval/publicationVersion 별도. PROFILE_PRIVATE는 core 전달을 무효화하지 않으며 전달의 선행 조건도 아님. 공개 승인/실제 공개는 미구현 |
| 여행 공유 | tripShareVersion을 별도 보관. TRIP_SHARE_CONFIRM은 아직 미구현이며 이번 실행에서 공유하지 않음 |
| 차량 활성 | origin=handoff/stored_preparation/demo_preset·core 버전·device/session·확인 시각. 처음 활성화 후 본인 여행은 유지 |
| 직접 시작 | stored_preparation은 확인한 core 버전. demo_preset은 원문/프로필/계획 준비가 전혀 없을 때만 고정값 생성. handoff/ACK 생성 없음 |
| 복원 | 같은 deviceId로 세션을 열고 최신 제한/활성 화면을 보고한 후 activeJourney 제공. 다른 장치는 활성 여정 인계 거절 |
| 미확인 응답 | 웹/차량은 명령 ID·본문을 먼저 동기 저장하고 영수증 확인. 명령을 새 ID로 자동 재실행하지 않음 |

지원 명령은 ONBOARDING_ANSWER, PROFILE_CONFIRM, PROFILE_PRIVATE, TRIP_SAVE, HANDOFF_PREPARE, CAR_SESSION_OPEN, CAR_STATUS, CAR_LOADED, CAR_START_TRIP의 9종입니다. target은 `{}`입니다. 웹 원문·client 소유권, 현재 질문 순서, core 버전, 차량 세션/제한, 활성화 뒤 변경 금지는 서버에서 검증합니다.

- v3 전용 파일은 `runtime/state-v3.json`입니다. 기존 `runtime/state.json`·v2 schema/예제·브라우저 `waymate.pending.v2`·차량 `handoff-v2` 설정은 자동 변환/삭제하지 않습니다.
- 현재 서버는 v2 명령을 400 INVALID_PAYLOAD로 거절하고, v2 저장소 경로를 잘못 지정하면 시작을 거절하며 덮어쓰지 않습니다. 과거 preset에서 원문을 복원하지 않습니다.
- v3 웹은 지원하지 않는 서버 버전을 거절하고 초안/pending을 유지합니다. 새 초안과 pending은 별도 v3 키이며 원문 초안은 client/run/답변 revision에 묶습니다.
- v3는 활성화 뒤 새 회차를 만드는 제품 초기화가 없습니다. 개발용 격리 테스트는 임시 저장소를 사용합니다. 초기화처럼 보이게 실제 내비 journal을 지우면 안 됩니다.

## 5. 실제 NaviHelper 조기 시험 결과

Pleos Connect 2.1 API34 Apple Silicon 에뮬레이터에서 NaviHelper **3.0.5**를 실제 공식 Maven 의존성으로 빌드·설치했습니다. 의존성 navi-data 3.0.4/navi-aidl 3.0.1을 lockfile에 고정했습니다. 배포 인터페이스의 콜백 철자는 `onWayPointInfo`입니다.

제품 흐름과 분리한 `realDebug` 시험 Activity입니다. `realRelease`에 시험 Activity/시험용 권한을 내보내지 않습니다.

```sh
cd mock-app/vehicle
./gradlew :app:assembleRealDebug :app:lintRealDebug
adb -s emulator-5554 install -r app/build/outputs/apk/real/debug/app-real-debug.apk
adb -s emulator-5554 shell am start --user 10 -n com.waymate.app.real/com.waymate.app.platform.navigation.NaviProbeActivity
adb -s emulator-5554 shell run-as com.waymate.app.real --user 10 cat files/navi-probe.json
```

[공식 SDK 설치](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/importing-sdk), [권한](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/declaring-permissions), [목적지](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/destinations), [경유지 예제](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/waypoint-settings), [콜백](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/event-listeners)를 확인했습니다.

| 시험 | 관측·판정 |
|---|---|
| SDK 연결 | initialize onConnected 수신, 목적지/경유지/route-state 조회 응답 확인 |
| 호출 전 기준 | 목적지 이름 없음·(0,0), 경유지 [], SAFE_GUIDING/isRouting=false |
| 시험 D 요청 | 공식 예제의 42dot, (37.48544722,127.03636666), poiId `36khp37hh8gqcm5nqhe5`. 사용자 버튼 동작으로 requestRoute 한 번 호출 |
| 호출 후 | 반환은 기록했지만 성공 처리하지 않음. 순정 화면에 42dot·50m, 조회 이름은 42dot, 좌표는 **(37.41289678,127.09383464)** |
| 종료 근거 | onRoutingCompleted 미수신, route-state의 ROUTE_GUIDING/isRouting=false는 관측했으나 D 좌표 불일치. 10초 후 unknown 유지 |
| M 추가·제거 | D 시작 조건 미충족으로 **실제 호출하지 않음**. 모의 성공으로 대체하지 않음 |
| 시험 정리 | 같은 시험의 42dot·경유지 없음 확인 후 순정 UI ‘안내 종료’로 종료. 다시 SDK 조회해 목적지 빈 값·(0,0), 경유지 [], SAFE_GUIDING/isRouting=false 확인 |
| 이력 | 원래 prepare attempt의 unknown 기록 유지. journal을 지우거나 자동 반복하지 않으며 시험 버튼도 pending 동안 차단 |
| 지도 배경 | 순정 UI가 열리고 SDK 조회는 되지만 배경 미표시는 해결하지 못함 |

좌표 불일치의 원인은 아직 확정하지 않았습니다. POI ID 해석/실제 데이터/에뮬레이터 동작을 분리해 조사하고, 시험 fixture와 복구 근거를 갱신한 뒤 추가/제거를 새 명시 승인으로 시험해야 합니다. 이번 결과는 실제 SDK 초기화·조회 증거이며 **내비 추가/제거 또는 제품 내비 연동 완료가 아닙니다.** 강릉 이야기의 ETA나 우회 시간 근거로 사용하지 않습니다.

로컬 원본은 `mock-app/runtime/navi-probe-observation.json`과 앱 전용 `files/navi-probe.json`에 있습니다. 시험 화면은 호출 직전 journal을 AtomicFile로 동기 저장하고, 실패/비활성/제한/unknown에서 자동 재호출하지 않습니다. 이 journal은 제품의 NAV_APPROVE/NAV_DISPATCH_BEGIN/NAV_REPORT 구현을 대체하지 않습니다.

## 6. 검증과 남은 일

- Node 22.22.2의 계약·실제 HTTP·복구 검증 **52개 통과**. v2/v3 golden, raw 보존·500 Unicode 한도, 원문 비노출, 분기 무효화, 명시적 빈 소개, 공개/core 분리, 직접 시작/가짜 ACK 금지, 활성화 뒤 웹 거부, 같은 장치 복원, 구버전 보존, 제한·동시성·저장 실패를 포함합니다.
- v3 예제 반복 생성의 동일성을 확인했습니다. 테스트는 로컬 실행 상태를 바꾸지 않습니다.
- Playwright 실제 웹에서 공백·이모지 입력, 전송 전 초안 새로고침 복원, 소개값 별도 선택·계획/전달 저장, 차량 ACK 후 읽기 전용 표시를 확인했습니다.
- 실제 Pleos 앱에서 웹의 파도/a-01/확인 소개/계획 → 서버 ACK → 홈을 확인했습니다. 앱 강제 종료/새 세션과 서버 재시작 후 같은 run/core/activation/ACK가 유지되고, CAR_LOADED는 기존 1건·CAR_START_TRIP은 0건으로 새 요청 없이 복원됨을 확인했습니다.
