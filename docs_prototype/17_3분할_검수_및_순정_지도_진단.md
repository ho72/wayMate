# Pleos 3분할 검수·순정 지도 진단

2026-11-12. 03번 §8.1과 09번의 **Driving View / 순정 내비 / wayMate** 동시 표시를 기준으로 검수했다. **3분할 화면 수정과 실제 경유지 제거·O01 ACK는 확인했으나, 순정 내비의 배경 지도 누락은 해결하지 못했다.** 지도 배경 복구나 전체 접근성 검수를 완료로 표시하지 않는다.

## 화면 수정과 검증

- 앱 한 창은 841×1210dp다. 종전의 `width >= 840` 판정이 세로 창을 넓은 화면으로 오인했다. 창의 가로·세로를 함께 확인하도록 바꾸고 홈·대화·결말을 세로 창에서 한 열로 배치했다. 확장 창은 두 열을 유지한다.
- 대화·결말은 좁은 창 전체를 세로 스크롤하며, 장면·일정 전환 시 시작 위치로 돌아온다. 상태와 선택값은 화면 밖에서 유지한다. 홈의 행동 버튼은 필요한 경우 다음 줄로 배치한다.
- 상대의 임시 캐릭터가 창 너비대로 가로로 늘어나는 문제를 수정했다. 캐릭터의 정사각형 비율을 유지한다. 새 3D·입 모양·음성 재생 구현으로 설명하지 않는다.
- 실제 3분할에서 홈, 모바일 준비 불러오기, 콘텐츠 목록, 공개 질문/답변, 말 전달, 만남, 내비 승인, 이동, 만남 재연, 최종 선택/별도 확인/대기, 두 결말, 친구 대화, 일정, 제한 화면, O01 정리/별도 승인/새 회차를 확인했다. 아래 증거의 상세 범위와 캡처를 함께 확인한다.
- 최종 설치 real APK와 로컬 빌드 SHA-256이 같다. 모의·실제 APK 빌드와 양쪽 Lint 통과(각 오류 0·기존 경고 23), Kotlin **39개**, Node **234개** 통과. 창 너비 841dp의 세로 창과 1682dp의 확장 창을 구분하는 회귀 테스트 2개를 추가했다.

검증 중 글자 배율 130% 변경은 순정 내비의 재시작과 경로 종료를 동반했다. **확대 글자 전체 검수는 통과로 계산하지 않는다.** 기본 배율로 복원했다. 실차의 읽기 거리·주행·오디오·프레임/메모리 성능도 이번 결과에 포함하지 않는다.

후속으로 시스템 배율을 유지한 채 **앱 Activity·Dialog만 130%로 적용한 기기 UI 테스트 7개와 확장 창 2개**가 통과했다. [18번](18_확장_창_및_글자_확대_검수.md)에 범위와 재현 방법을 기록했다. 위 시스템 전체 배율 전환의 한계는 남는다.

## 실제 내비·선택·초기화

실제 SDK/ACK·회차·APK 증거는 [검증 JSON](evidence/three-pane-validation-2026-11-12.json)에 있다. 전체 runtime 저장소·자격 증명·원문 로그는 커밋하지 않는다.

선별 원본: [홈](evidence/three-pane-home-2026-11-12.png), [질문 답변](evidence/three-pane-answer-2026-11-12.png), [최종 선택](evidence/three-pane-final-choice-2026-11-12.png), [정리 승인](evidence/three-pane-reset-review-2026-11-12.png), [순정 내비 단독](evidence/native-map-alone-2026-11-12.png). 로컬 갤러리의 최종 원본 32장 모두 계기판 렌더 영역이 포함되어 있음을 다시 확인했다.

1. D=(37.48544722,127.03636666), 경유지 없음의 실제 이중 관측에서 운전자가 검토하고 승인했다. 앱의 `addWaypoint` 1회와 applied·D 유지·M ID를 확인했다.
2. 앱 재설치/재진입에서 SDK journal이 보존되고 추가 물리 호출이 없음을 대조했다. 검수 중 순정 내비의 안내 종료가 있었으므로 **끊김 없는 한 번의 왕복 시험으로 설명하지 않는다.** 순정 UI에서 이전 시험 D/M을 별도로 복원했고, 실제 SDK 관측으로 D·M 이름/ID/좌표가 원래 승인 기록과 일치함을 다시 확인했다. 이 복원은 앱의 새 추가 호출로 계산하지 않는다.
3. O01의 만남 시작/종료는 준비된 가상 재연이다. A 차량에서 함께 선택을 별도 확인하여 제출한 뒤, B의 선택은 공개되지 않는 대기를 확인했다. O01의 준비된 B 응답으로 함께 결말을 열고, 재시연에서 A=내 캐릭터·B=함께로 각자 결말을 확인했다. 실제 상대 접속·GPS 도착·실시간 음성으로 설명하지 않는다.
4. O01 초기화에서 운전자가 다시 검토·승인했다. 앱의 `removeWaypoint` 1회, removed·D 유지·M 없음, 실행 차량의 실제 ACK 뒤 새 회차 전환을 확인했다. SDK 호출·서버 상태를 수동 성공값으로 덮어쓰거나 journal/앱 데이터를 지우지 않았다.
5. 새 회차는 정상 시연 API로 모바일 준비·최종 매칭을 만들고 차량의 불러오기 버튼으로 다시 열었다. 다음 시연을 위한 준비이며 이전 회차의 검증 사실을 대체하지 않는다.

## 지도 배경: 미해결

후속 [19번](19_순정_지도_추가_진단_및_Playground_설정.md)에서 wayMate 미설치·프로젝트 키 미입력의 별도 새 AVD에서도 재현했다. 자체 타일 인증 갱신/304 기록과 GPS 입력 수락의 한계를 구분했으며, Playground에서 필요한 항목을 공식 문서와 대조했다. 여전히 지도 복구 완료로 표시하지 않는다.

환경은 Apple M3 Pro/18GB, Pleos Connect 2.1.0/API34 ARM64, 순정 내비 3.3.2-rc5-hotfix.3, NaviHelper 3.0.5다. wayMate를 가린 순정 내비 단독 창에서도 안내 문구·장소·경로 정보는 나타나지만 배경이 비었다.

| 비교 | 결과 |
|---|---|
| Android Emulator 37.2.13, 기존 host 렌더링 | 배경 누락 |
| 37.2.13, Cold boot·host·Vulkan 비활성 | 배경 누락 |
| 37.2.13, software 렌더링 | 배경 미복구, 계기판 표시/성능 악화 |
| Google 공식 37.1.11 Stable를 임시 폴더에서 실행, host·Vulkan 비활성 | 같은 문제 재현 |
| 순정 내비 2D/3D 전환·내비 프로세스 재시작 | 배경 미복구 |
| 시험 한국 GPS 및 체크섬이 유효한 NMEA 입력 | 배경 미복구 |

인터넷 validated·호스트/게스트 UTC 일치·순정 내비 공통 인증 성공·지도 초기화 완료·static image tile provider 시작을 확인했다. 지도 초기화 부근에 GL 0x501 오류와 레이어 누락 경고가 있으나 **원인으로 확정하지 않았다.** `connect_empty` 스타일은 배경·해안선·slot으로 구성돼 있지만, 순정 지도 합성 구조의 정상 동작 여부는 제공사 확인이 필요하다. 사용자 Playground 키 누락이나 특정 권한 문제가 원인이라고 단정하지 않는다.

기존 SDK를 교체하거나 AVD를 초기화하지 않았다. 비교용 버전은 `/tmp`에만 풀었고, 종료 시 설치돼 있던 37.2.13과 프로젝트의 GLES 실행 스크립트로 복원했다.

Pleos 측에 확인할 내용은 **이 ARM 이미지/순정 내비 조합의 배경 지도 지원 및 필요한 설정, Apple Silicon 렌더링 알려진 문제, 권장 이미지·내비 수정 버전**이다. 위 재현 조건과 선별 캡처를 문의 자료로 사용할 수 있다. 실제 외부 문의는 발송하지 않았다.

## SDK·프로젝트 정보

- 현재 차량 상태 조회와 NaviHelper 연동에는 추가 사용자 키가 필요하지 않다. 앱은 `NAVI_ROUTE`, `NAVI_ROUTE_SEARCH`를 선언하고 별도 순정 내비 창을 사용한다. 내비 지도를 앱 안에 임베드한 구현이 아니다.
- [프로젝트 안내](https://document.pleos.ai/docs/pleos-only/create-my-project)상 Vehicle State/NaviHelper는 별도 신청 없이 사용할 수 있다. 프로젝트 ID(Key)는 추후 앱 심사 시 사용하고, Emulator 2.1.0 이후에는 CRN 입력이 필요 없다.
- [TTS 안내](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/TextToSpeech/intro)상 서버 기반 HYBRID/SERVER 음성은 앱 등록 자격 증명이 필요하지만 ON_DEVICE TTS는 등록 없이 사용할 수 있다. 서버 기반 음성 연동을 선택할 때 Client ID/Secret 및 프로젝트의 실제 SDK 사용 가능 상태를 확인한다. Secret을 채팅이나 저장소에 올리는 절차로 만들지 않는다.
- 현재 앱의 Android TTS가 서비스에 연결되지 않는 문제와 Pleos 음성 SDK 연동은 별도 후속 작업이다. 이번에는 자막과 미지원 안내를 검수했으며 실제 낭독·마이크 입력은 통과로 표시하지 않았다.
