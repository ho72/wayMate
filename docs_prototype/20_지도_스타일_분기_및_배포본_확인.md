# 지도 스타일 선택 분기·공식 배포본 확인

2026-11-12. [19번](19_순정_지도_추가_진단_및_Playground_설정.md)의 후속이다. **현재 순정 앱의 `coral` 환경이 `connect_empty`를 직접 선택하는 구체적인 분기를 확인했다. 도로 배경 복구는 아직 미완료다.** 사용자 Playground 설정과 SDK 사용 신청을 반복하는 대신, 이 분기가 공개 이미지의 의도된 제한인지와 공식 전환 설정·수정본을 제공사에 확인해야 한다.

## 배포 버전과 지원 문서

2026-11-12 공개 저장소의 `raw-releases` 자산 목록은 5개이며 다음 페이지가 없다. ARM/x86 이미지·피드 4개와 Host Display Bridge 1개다. 별도 순정 내비 APK나 더 새 ARM 이미지 수정본을 공개 목록에서 찾지 못했다. 비공개 지원용 수정본의 존재 여부까지 부정하는 결과는 아니다.

[공식 설치 안내](https://document.pleos.ai/docs/connect/guide/getting-started/application-development/setup-connect-sdk-emulator)는 Mac ARM 이미지, API34, RAM 4GB와 cold boot를 안내한다. [공식 GPU 요구사항](https://document.pleos.ai/docs/connect/guide/getting-started/application-development/configure-pleos-connect-emulator)은 NVIDIA/AMD 제품을 나열하지만 Apple M3에서 순정 도로 배경 표시가 보장되는지 명시하지 않는다. Mac 이미지가 제공된다는 사실과 M3의 모든 지도 렌더링 기능 지원은 구분한다.

목록의 Host Display Bridge는 [폼 팩터 가이드](https://document.pleos.ai/docs/pleos-only/app-test-guide/form-factor-test-guide) 및 배포본 README상 **가상 디스플레이 생성·제거용**이다. 기본 순정 지도 배경을 내려받는 구성 요소로 안내되지 않아 실행·설치하지 않았다.

## 구체적으로 확인한 스타일 선택

설치된 **공식 SDK의 읽기 전용 `system.img`**에서 factory `Navi42.apk`를 로컬 진단 폴더에 추출해 분석했다. 실행 중인 AVD의 보호된 앱 데이터·APK를 수정하지 않았다. 분석 대상 factory APK의 SHA-256은 `0d50f70c2d3d8a553bf203e60c0cf238bc383d1573997debd144eb2dfff7cd31`이다. 이 값은 factory 파일의 해시이며 실행 중 APK를 다시 읽어 바이트 일치를 검증한 값으로 표현하지 않는다.

`ai.umos.maps.android.navigation.app.data.datasource.remote.mapstyle.MapStyleRemoteDataSourceImpl`의 `getMapStyles`에서 다음 동작을 확인했다.

1. 환경 인자가 `coral`이면 일반 스타일 목록 API 요청 분기로 가지 않는다.
2. `dataCollection` / `connect_v2` 모델 하나를 만들고, 스타일 URL로 `https://a.tile.static.maps-coral.umos.ai/styles/42dot/connect_empty`를 직접 지정해 반환한다.
3. 기존 및 별도 AVD의 초기화 로그에도 위 URL이 관찰됐다.
4. 그 공개 스타일은 현재 HTTP 200이며 `coastline` 소스 하나와 background/fill/slot/slot 레이어만 있다. **도로 레이어가 선언되어 있지 않다.**

따라서 최소 스타일을 단순히 서버에서 발견한 단계보다 근거가 강해졌다. **현재 환경에서 왜 그 스타일이 선택되는지는 특정 코드 분기와 런타임 URL로 설명할 수 있다.** 도로 표시를 위한 다른 합성 경로나 제공사 의도·지원 조건까지 확인한 것은 아니므로, 모든 렌더링 문제의 유일한 원인으로 확정하지 않는다.

현재 wayMate가 사용하는 공개 NaviHelper API에 프로젝트 키를 추가해 이 순정 앱의 분기를 바꾸는 절차는 확인되지 않았다. 앱 내부 구현을 wayMate의 공개 SDK 기능으로 간주하지 않는다. APK 패치·인증값 재사용·검증 우회로 시연 화면을 성공 처리하지 않았다. factory APK, 디컴파일 원문, 원문 로그는 커밋·문의 첨부에서 제외한다.

## GPS·그래픽 추가 비교

기존 AVD는 유지한 채 별도 `emulator-5556`에서 같은 프로필·host GLES·Vulkan 비활성·cold boot에 **`-no-passive-gps`만 추가**해 비교했다. 이 옵션은 설치된 Emulator 37.2.13의 도움말과 [AOSP 옵션 정의](https://android.googlesource.com/platform/external/qemu/+/refs/heads/emu-master-qemu-release/android/android-emu/android/cmdline-options.h)에 존재한다.

- 올바른 체크섬의 GGA/RMC 30문장을 15초 공급했고 각 console `OK`를 확인했다.
- 수집한 순정 프로세스 로그에서 NMEA 체크섬 오류는 0개였다. `MapComplete`·스타일 로드는 완료됐지만 도로 배경은 계속 없었다.
- **오류 0개만으로 정상 NMEA 소비를 증명하지 않는다.** 성공 parser 이벤트를 별도로 관측하지 못했고 엔진 위치 로그도 남은 한계가 있어, 정상 GPS 품질 검증 완료로 계산하지 않는다.
- SurfaceFlinger의 실제 드라이버는 Apple M3 Pro / OpenGL ES **3.0**이다. 호스트에는 `gldCopyBufferSubData: NEEDS IMPLEMENTATION` 경고도 있었다. 이 경고가 해당 도로 누락의 직접 원인인지는 확인하지 못했다.

도로 복구 효과가 검증되지 않았으므로 기본 `run-emulator.sh`와 기존 AVD 옵션은 바꾸지 않았다. 비교 AVD는 정상 종료했다. 기존 AVD의 실제 SDK journal 11개 기록은 전후 바이트 동일하며 계기판·순정 내비·wayMate 배치를 보존했다.

## 공식 확인 요청

확인할 사항은 다음과 같이 좁혀졌다.

1. 공개 ARM 이미지의 `coral → connect_empty` 선택이 의도된 지도 표시 제한인가, 현재 배포본의 설정/구현 문제인가?
2. 일반 개발자가 도로 표시를 켤 수 있는 **공식 환경·스타일 설정**이 있는가? 별도 허가가 필요하면 담당 창구와 절차는 무엇인가?
3. 해당 분기를 변경한 순정 내비 APK 또는 시스템 이미지의 지원 버전·공식 배포 경로는 무엇인가?
4. Apple Silicon의 도로 지도 렌더링 지원 조건과 권장 백엔드는 무엇인가?

[공식 FAQ](https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/vehicle-app-faq)에 안내된 `partnership@pleos.ai`용 문의 본문을 로컬에 준비하고 외부 발송 승인을 요청했다. 승인 전 발송하지 않는다. 사용자 키·Secret·원문 로그·APK는 포함하지 않는다. 사용자 프로젝트의 NaviHelper와 Vehicle State는 이미 모두 **사용 가능**으로 확인됐으며 현재 추가 키 전달을 요청할 근거는 없다.
