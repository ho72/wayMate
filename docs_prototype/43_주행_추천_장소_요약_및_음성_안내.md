# 주행 추천 장소 요약 및 음성 안내

2026-11-15. 기존 DrivingScreen의 큰 정적 캐릭터·고정 헤더·간편 모드를 유지하고, 하단에 한 장소의 추천 요약 카드를 추가했다. 2분할은 좌측 캐릭터·우측 추천 카드/음성 조작, 3분할은 캐릭터 아래 하단 카드의 세로 구성을 사용한다. 두 분할 모두 스크롤 없는 요약이다. 2분할에 세로 구성을 그대로 적용했던 초기안을 사용자 피드백에 따라 수정했다.

## 표시와 전환

- 하단 반투명 카드: 추천 종류/가상 표시, 장소명, 핵심 소요 시간, 짧은 추천 이유. 휴식 바다쉼터와 식사 바다한상의 고정 예시를 지원한다.
- 정차에서 휴식/식사 목록 또는 상세를 보고 주행 제한 모드로 바뀌면 해당 질문 종류의 첫 고정 예시를 주행 카드로 표시한다. 기존 상세 흐름의 unavailable 처리와 내비 요청 잠금은 유지한다. 정차 복귀 시 자동 안내·승인·선택을 실행하지 않는다.
- 현재는 질문 종류의 첫 예시다. 실제 검색 결과/선택 장소의 실시간 전달, 주행 중 음성 검색·후보 변경·장소 확정·내비 연동은 미구현이다.
- 미확인/차단 모드에서는 추천 정보를 숨긴다. 캐릭터는 음원 재생 중에도 정적이며 목록·상세·경로 조작을 추가하지 않는다.

## 안내 재생

- 후속 요청으로 추천 카드의 ‘추천 안내 듣기’를 제거했다. 새 추천 결과의 안내 요청 ID가 있을 때, 주행 모드·창 활성·서버 허용·유효 lease·재생 준비 조건이 갖춰지면 한 번 자동 안내한다. 재생 호출 전에 요청을 처리 완료로 기록하므로 같은 결과의 화면 복귀·분할 전환·서버 상태 갱신으로 다시 시작하지 않는다.
- 보조 조작은 배경 없는 ‘안내 멈추기’다. 캐릭터가 현재 출력하는 안내를 중단한다. 사용자의 마이크·음성 인식·대화 연결을 종료하는 기능이 아니다. 안내 대기 중 누르면 해당 자동 안내 요청도 취소한다.
- 포커스 상실·화면 비활성·제한/lease 만료·화면 이탈 시 미처리 자동 안내도 소비하고 음성을 중단한다. 허용 상태가 복귀해도 이미 소비한 결과는 자동 재개하지 않는다. 기존 추천 없는 ‘친구 한마디 듣기’는 수동 동작을 유지한다.
- 추천 데이터와 음성 대사는 shared/config/driving-recommendations.json 한 곳에서 관리한다. Gradle은 표시 데이터/허용 대사를 생성하고 음원 생성 스크립트도 같은 JSON을 읽는다.
- 주행 음성 허용은 기존 서버 fresh/세션/foreground·CarUxRestrictions·audio lease 조건을 유지하며, 대사 허용 목록에 고정 추천 2개만 추가했다. 임의 문자열·상대 메시지·수정된 대사는 허용하지 않는다.
- Yuna 합성 음원 두 개를 추가했다. AAC 변환기가 없는 호스트에서는 ffmpeg를 사용하고, 비어 있는 음원을 성공으로 처리하지 않도록 검사한다. 기본 대화나 STT 녹음이 아니다.

## 이번 확인 범위

mockDebug 빌드 성공, 고정 음성 허용 정책 JVM 테스트 2개 성공. 두 새 음원의 파일·자막 SHA-256 일치와 길이(휴식 약 8.9초, 식사 약 9.6초)를 확인했다. 정차 상태의 Debug 호스트에서 휴식 안내 MediaPlayer의 prepared_start → prepared_end/finished를 확인했다.

[최신 캡처](evidence/driving-autoplay-2026-11-15/README.md)는 실제 1682×1210/841×1210 앱 창에 주행 UI를 표시한 미리보기다. 실제 차량은 P/0을 유지했다. Debug 호스트의 로컬 음성 확인은 실제 주행 제한·실차 오디오 검증과 구분한다. 나머지는 [36번](36_차량_UI_검증_필요_항목.md)에 기록했다. PR은 생성하지 않았다.

## 자동 안내 후속 확인 · 2026-11-15

mockDebug 빌드 후 정차 Debug 호스트에서 휴식 추천의 무탭 자동 시작/완료를 확인했다. 같은 프로세스의 2→3분할 전환 후 휴식 안내 시작 로그가 한 건임을 확인했다. 식사 추천으로 새 결과를 표시한 뒤 ‘안내 멈추기’를 눌러 interrupted를 확인했고, 같은 장면을 다시 전달해도 재시작되지 않았다. 이 검사는 실제 주행·서버 통합 검증을 대신하지 않는다. 기존 음성 허용 정책 JVM 2개는 이전 단계 결과이며 자동 안내 변경 후 재실행하지 않았다.

현재 추천 입력은 정차 화면에서 선택한 고정 질문 종류이며 STT가 아니다. 실제 운전자 음성 인식·발화 종료/타임아웃·잡음 대응·다른 후보 요청·음성 선택/확정은 미구현이며 36번 별도 검증 필요 항목이다. UI에 ‘듣고 있어요’나 열린 마이크를 표시하지 않는다.
