# 두루밋 차량 전체 페이지·화면 전환

2026-11-15 · 08번 화면 설계서의 차량 페이지 중 빠졌던 **WF-034~039·042~043·044~051, 총 16개**를 구성했다. 디자인 정밀화보다 페이지 존재·진입·뒤로 가기·분기를 우선한다. 서비스 확정 이름은 **두루밋**이며 앱 표시명·웹 제목/브랜드·에이전트 소개를 변경했다. 기존 앱 ID·패키지·DB·전달 계약의 내부 식별자는 유지한다.

## 구현 경계

- 새 E/O 흐름은 **페이지 전환용 로컬 시연**이다. 모든 화면에 미리보기 상태를 표시하며 실제 순정 내비·마이크·다자 통화 성공으로 표시하지 않는다. `시연 조건 선택`에서 가상 목적지 있음/없음/같은 일정과 성공/실패/미확인 분기를 고른다.
- `VehiclePageFlow`는 서버·내비 드라이버를 참조하지 않는 순수 상태다. 기존 공유 만남 `NAV_APPROVE`를 재사용하지 않는다. 가상 주소·좌표는 실제 내비로 전달하지 않는다.
- 039의 저장 일정은 본인 계획을 읽는다. 실행 흐름은 별도의 가상 일정 장소로 미리 본다. 개인 계정에서 받은 실제 일정은 기존 ‘내 계정 여행’ 화면에 유지한다.
- 042의 상대 MC 동의는 사용자가 선택하는 시연 장면이다. 일반 통화 동의를 대체하지 않는다. 실제 `CALL_END`는 사용자가 `통화 종료`를 누를 때만 기존 명령을 보낸다.
- 043의 기록·장식은 현재 시연 화면에만 보관한다. 같은 외형에 중복 반영하지 않으며 실제 프로필 외형·장기 기억을 변경하지 않는다.
- 051은 정차 상태의 자막 시연이다. 실제 주행 중 화면은 기존 `DrivingScreen`이고 마이크·음성 문답 지원을 넓히지 않는다.
- 정차 제한/포커스 상실/앱 비활성화 시 이전 승인 화면을 폐기하고 진행 중 모의 안내는 미확인으로 전환한다. 정차 복귀·화면 복원으로 승인·대화·요청을 자동 실행하지 않는다.
- 미확인 모의 요청은 홈 복귀와 저장 상태 복원 뒤에도 새 요청을 막는다. 이전 요청의 늦은 결과는 현재 요청에 적용하지 않는다.
- 대화·결말은 `SaveableStateProvider`로 보관해 MC/일정/후기에서 돌아왔을 때 원래 세부 화면을 유지한다.

## UI 먼저 확인하기

Debug 차량 홈의 **추가 차량 화면 미리보기**를 누르면 서버·시연 단계와 별개로 추가 16개 페이지를 바로 열 수 있다. 목록에서 WF를 선택하거나 **장소 질문부터 흐름 시작**으로 들어간다. 각 화면의 **추가 차량 화면 목록**으로 복귀한다. 개인 안내 요청 중 화면은 살펴볼 수 있도록 멈춰 있으며, 상단 **다음 모의 결과 화면 보기**를 누르면 다음 결과 화면으로 이동한다.

Debug 전용 `VehiclePagesPreviewActivity`는 모의 여행만 사용한다. 실제 계정·상대 상태·내비 journal에 접근하지 않으며, 실제 주행 제한은 계속 적용한다. 일반 통화·함께 결말 같은 선행 상태 없이 MC·기록 페이지도 바로 볼 수 있다. 이 독립 미리보기에서 일반 통화/결말 복귀 버튼은 화면 목록으로 돌아간다. 실제 앱에서 같은 버튼은 기존 통화/결말 화면으로 복귀하도록 연결했다.

```sh
adb shell am start --user 10 -n com.waymate.app.mock/com.waymate.app.ui.testing.VehiclePagesPreviewActivity
```

실제 앱 ID는 `com.waymate.app.real`, 모의 앱 ID는 `com.waymate.app.mock`이다. 패키지 내부 경로는 동일하다. 2026-11-15 mock/real Debug APK 빌드를 마치고 데이터를 유지하는 갱신 설치를 했으며, 모의 앱의 페이지 목록이 Pleos 화면에 표시되는 것을 확인했다.

PR은 생성하지 않는다. UI를 먼저 진행하고, 검증 항목·앞선 실행 결과·실패/미완료는 [36번 별도 검증 필요 문서](36_차량_UI_검증_필요_항목.md)에 남긴다.
