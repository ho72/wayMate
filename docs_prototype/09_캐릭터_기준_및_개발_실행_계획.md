# 캐릭터 기준 및 개발 실행 계획

작성일 2026년 11월 11일 · 갱신일 2026년 11월 12일 · 버전 0.3 · 구현 착수 기준과 후속 우선순위

## 1. 이번 대화에서 확인한 기준

- 구현 범위·대본·상호작용·계약·검수는 01~05 v0.8, 역할 경계는 06 v0.4, 목표 화면은 08 v0.4을 따른다. 기존 v2 기록은 07에 보존하고, 이후 착수한 v3 첫 구현과 내비 시험 결과는 [10](10_v3_여행_준비_차량_홈_및_내비_시험.md)에 기록한다.
- 캐릭터 외형은 사용자가 채택한 [파란 아기 드래곤 시안](../mock-app/assets/images/characters/blue-dragon-v1/reference.png)을 기준으로 한다. [출처·상태](../mock-app/assets/images/characters/blue-dragon-v1/README.md)는 소재와 함께 관리한다.
- 정교한 3D 렌더 느낌을 유지한다. 현재 시안은 정적 PNG이고 실제 3D 모델·리깅·동작 원본은 없다. 외형 채택을 애니메이션 완료로 표시하지 않는다.
- **실제 순정 내비 SDK 연동을 필수 개발 기준으로 둔다.** 모의 내비는 개발·실패 검증에 사용하되 실제 연동 완료를 대신하지 않는다. 기존 문서의 모드 선택 항목은 이 사용자 우선순위를 반영해 관리한다.
- **대표 개발·검수 배치는 왼쪽 Driving View / 가운데 순정 내비 / 오른쪽 wayMate의 3영역 동시 표시다.** 내비를 뒤로 보내고 앱이 두 창을 쓰는 넓은 화면만으로 대표 검수를 마치지 않는다. 앱 한 창의 portrait 너비에서 홈·일정·대화·만남·승인·결말의 가독성과 터치·복원을 확인하고, 확장 landscape는 추가 대응으로 검수한다. Pleos 2.1/API34에서 window bar로 한 창 모드로 전환한 뒤 세 영역의 실제 표시를 확인했다. 3분할 화면 수정·실제 추가/제거·O01 ACK의 후속 검증은 [17번](17_3분할_검수_및_순정_지도_진단.md)에 기록했다. 순정 내비 배경 지도 미표시는 별도 미해결 문제다.
- 디자인 미확정 부분은 03·08의 배치와 상태를 기준으로 구현하고, 색·간격·외형 소재를 바꿀 때 업무 로직을 재작성하지 않도록 분리한다.
- 개인 장소·일정 확장 E는 기존 안내대로 계약 갱신 후 별도 구현한다. 차량 상태 안내·일부 제어는 필요한 기능을 선정해 지원 검증부터 진행하며 모든 차량 제어를 새 필수 범위로 추가하지 않는다.

## 2. 현재 구현과 개발 가능한 범위

이 계획 수립 당시 확인한 기반은 웹·서버·차량 프로젝트, v2 본인 프로필/고정 여행 저장·HTTP 전달·ACK·영수증 복구·제한 잠금이다. 기존 검증은 07에 기록돼 있으며 목표 v3 전체 기능 검수가 아니다.

개발 작업은 다음 단계까지 수행할 수 있다.

| 영역 | 구현·검증할 결과 | 완료를 구분해야 하는 부분 |
|---|---|---|
| 공통 계약·서버 | v3 schema·예제·상태 전이·공개 필터·명령/영수증·복원·초기화 | 기존 v2 기록 보존·전환 정책, 문서와 다른 임의 입력 변환 금지 |
| 모바일 | M01 자유 입력·후속 질문·소개, M02 계획, M03 공개/후보/이유, M04 매칭/시간 확인·전달 | 실제 LLM·실제 상대 접속으로 표시하지 않음 |
| Pleos | P01 연결/본인 여행 수신·P02 홈/콘텐츠·P03 만남/실제 내비·P04 결말 | 탑승 후 폰 재조작 없이 이동 경험. 차량 추천/신규 매칭 없음 |
| 캐릭터 | 채택 외형 적용, 대기/발화/중단 상태, 표정·음성 재생 연결 | 투명 소재·일관된 입/눈/동작 세트 제작·실차 성능은 별도 검증 |
| 운영 패널 | 문서의 현재 요청에 대한 B 응답·시연 시간·오류·재시연 제어 | 대본 응답·통화 샘플을 실제 상대 사용자 통신으로 설명하지 않음 |

| 차량·음성 확장 | 선정한 상태 조회·알림·지원 제어, TTS/STT·포커스·수명주기 연결 | 현재 제공 서비스·권한·모드·실제 주행 허용을 확인하기 전 보장하지 않음 |
| 통합·인계 | 자동 테스트·APK·에뮬레이터 검수·실행 안내·재현 가능한 시연본 | 실차 검증·서비스 운영·스토어 심사 완료는 별도 결과 |

## 3. 개발 순서와 첫 산출물

### 1단계 · 기존 내비 증빙 확인과 v4 연결·전달 설계

W01/W03/W06에 대응한다. 04의 SDK 시험 경로와 권한을 확인하고, 현재 순정 내비의 지도 배경 미표시 원인을 조사한다. 초기화 → 현재 목적지/경유지 조회 → 명시 승인한 시험 경유지 추가 → 실제 반영 확인 → 명시 승인 후 제거·기존 목적지 확인을 수행한다. 실패·미확인·지원 문제는 그대로 기록한다.

현재 v3의 원문/소개·prepared_trip·차량 활성/실제 내비 기반을 보존한다. 새 v4 목표는 모바일 매칭·connected/my_trip 전달·현재 공개/관계 검증으로 별도 전환한다. v2/v3 상태 파일은 보존하고 새 v4 상태의 생성·호환 거부·초안 보존 정책을 명시한다. 폼에 자유 입력만 추가하고 v2 preset으로 치환하는 방식은 사용하지 않는다.

**첫 산출물:** 실제 SDK 시험 코드·관측 기록·미해결 항목, v4 계약과 소비자 전환 범위. 성공 여부는 아직 미검증이다.

### 2단계 · 탑승 전 준비에서 차량 홈까지

W03~W05/W10/W11의 첫 연결 부분에 대응한다. 현재 v3의 M01/M02 → prepared_trip → P01/차량 직접 시작 → 본인 홈은 구현 기반으로 보존한다. 새 목표의 연결 포함 전달은 다음 단계에서 모바일 매칭과 함께 구현한다. 채택한 드래곤을 표시하되 원문 온보딩은 차량에 전달하지 않는다. 휴대폰을 닫고 앱 재진입·서버 재시작 뒤에도 현재 여행을 복원한다.

**완료 기준:** 바꾼 별명·외형·확인 소개값·계획이 일치하고, 준비 수신과 차량 직접 시작의 출처가 구분되며 가짜 ACK가 없다.

### 3단계 · 모바일 추천·연결에서 차량 대화까지

W07~W12에 대응한다. 모바일 M03 공개/추천 → M04 요청·B 응답·시간 확인 → v4 connected 준비/차량 ACK → Pleos 대표 콘텐츠를 구현한다. 운영 패널의 B 이벤트와 서버 상태를 실제로 연결한다. 대본·캐릭터 소개·상대의 응답을 구분하고 거절·취소 뒤 본인 여행을 유지한다.

### 4단계 · 만남·실제 내비·두 결말

W13/W14에 대응한다. 장소·시간 합의와 운전자 내비 승인을 분리하고, 실제 NaviAdapter의 결과를 P03에 연결한다. 취소·제거·미확인·앱 재시작에서 중복 물리 호출을 방지한다. P04의 A·B 동시 선택과 함께/각자 결말·재시연을 연결한다. 같은 단계에서 서로의 선택을 보지 않고 독립 제출하며, 양쪽 제출 후에만 결과를 확정한다. 첫 개방·재시연 모두 B 제출에 A의 선행 선택을 요구하지 않는다.

개인 휴식·식사 E를 구현할 때는 공유 만남 명령을 재사용해 우회하지 않고 관련 계약·검수를 먼저 추가한다.

### 5단계 · 캐릭터 동작·음성·전체 검수

캐릭터는 선정 외형과 상태별 동작 소재를 연결한다. 기본 방향은 동일 캐릭터에서 미리 만든 동작을 재생하는 방식이며 실시간 3D 엔진 도입은 별도 판단한다. 정적 시안 한 장만으로 연속 동작이나 정교한 립싱크가 완성되지는 않는다.

실제 재생 시작/종료·포커스 상실과 캐릭터 발화를 맞추고, 앱 가림·비활성·제한에서 중단한다. 주행 음성은 V05 지원 검증 전까지 현재 차단을 유지한다. 최종 외형 세부 수정은 같은 상태·콜백 경계를 유지해 교체한다.

W15/W17의 적용 Q·Q28과 서비스 가설 V를 구분해 기록하고, 실제 내비 증빙·APK·서버·시연 데이터·소재·미완료 항목을 같은 버전으로 인계한다.

## 4. 실행 방식

53개 와이어프레임은 공통 화면과 대기·승인·실패 등의 상태 분기로 묶어 구현한다. 한 화면을 끝까지 장식한 뒤 다음 화면으로 이동하기보다, 실제 데이터와 연결된 여정을 먼저 완성하고 세부 시각 요소를 다듬는다.

담당자·개발 참여 인원·가용 시간·마감은 아직 미정이다. 이 계획으로 새 제출 마감이나 인원별 처리량을 정하지 않는다. 새 기능·산출물은 해당 구현과 검증이 끝난 뒤 07 및 05의 실행 기록에 반영한다. 이 문서는 실행 계획이며 단계별 실제 결과는 [10 실행 기록](10_v3_여행_준비_차량_홈_및_내비_시험.md)에서 구분한다.

## 5. 현재 구현 이후 개발 우선순위

2026-11-12 기준 모바일 매칭·차량 전달/홈·만남 동의/실제 내비, O01 안전한 초기화, P02 공개 문답/말 전달, P03 재연/P04 독립 선택·결말·재시연은 [13](13_v4_화면_전환_및_연동.md)~[16](16_만남_재연_및_P04_두_결말.md)의 부분 구현·검증이 있다. PR #3~#5 리뷰 수정까지의 통합 회귀는 Node 234개·Kotlin 37개다. 아래는 남은 작업 순서이며 전체 Q 통과를 뜻하지 않는다.

| 순위 | 다음 작업 | 완료 기준·근거 |
|---|---|---|
| 1 | DM07 일반 통화 샘플과 실제 음성 재생 | P02 제안·양쪽 동의·준비된 샘플/자막·종료/거절/취소·늦은 동의 무효까지 연결한다. 실제 음원 재생·포커스·가림/제한 중단을 확인한다. 현재 TTS는 등록됐으나 엔진 미바인딩이므로 원인을 확인하고 준비된 오디오 재생과 TTS 결과를 각각 기록한다. 재생 실패는 자막/중단이며 실제 상대 통신으로 표시하지 않는다. Q05·Q10, 03 §5.6·04 음성 계약 |
| 2 | O01 실패·unknown·복구 분기 | NAV_MOCK_RESULT의 모의 add/remove 성공·실패·unknown·재시도와 현재 요청 연결을 구현한다. 실제 기록과 모의 결과를 섞지 않는다. RECOVERY_CONFIRM은 실제 재조회/처리 종료/자기 경유지 정리를 검증한 절차가 있을 때만 연다. 증빙 없는 강제 초기화나 ACK 인수로 우회하지 않는다. Q14~Q16·04 §9.4 |
| 3 | 전체 여정 리허설과 상태 복원 검수 | 모바일 M01 직접 상담→M04 연결/시간 확인→폰 닫기→차량 수신·콘텐츠/통화·만남/내비·두 결말·재시연·O01 정리를 같은 버전으로 끝까지 확인한다. my_trip·거절/취소·재시작·늦은 응답도 별도 검수하고 모든 차량 단계의 본인 일정 표시를 확인한다. 실제 경로와 가상 카페/시각을 구분한 증거·실행 안내를 남긴다. Q28·Q29·Q11~Q13 |
| 4 | 캐릭터 최소 동작·화면 마감과 시연본 인계 | 기존 3D 렌더 느낌의 외형을 유지하며 소수의 대기/실제 발화/중단 상태 소재부터 연결한다. 음성 시작 콜백과 중단을 기준으로 동작하고 제한 중 반복 동작을 막는다. 최종 소재에서 실제 화면 가독성·프레임/메모리·APK/서버 재현과 발표 흐름을 확인한다. 실시간 3D·정교한 립싱크를 기본 완료 조건으로 확대하지 않는다. W15·W17, Q10·Q17 |

V05의 실제 주행 음성·DO/권한·플랫폼 지원 조사는 1순위와 함께 먼저 진행하되 확인 전 주행 차단을 해제하지 않는다. Q28 전체 리허설은 1·2순위 기반이 갖춰지면 완료하며 현재 가능한 자막 여정 리허설은 그 전에 진행할 수 있다. 실차 검증과 사용자 가설 V는 기능 Q와 별도로 기록한다.

P05 후기/장식·이유 입력, MC/게임, 개인 장소·일정 확장 E, 실시간 상대 통신·생성형 대화는 필수 목업 완주 이후다. 개발 담당·참여 인원·마감은 기존 미정 상태를 유지한다.
