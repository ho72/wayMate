## 실행과 인계

`mock-app/README.md`와 차량 README를 현재 v4 흐름으로 정리했다. `vehicle/scripts/verify-first-pass.sh`는 서버·APK·JVM·Lint를 검사하고 `device` 인자는 실제 음원/포커스·UI 회귀를 실행한다. 창 크기별 기존 회귀는 `verify-window-ui.sh wide|font`를 별도로 사용한다.

기본 포트 3000으로 두 APK를 빌드한 뒤 `node scripts/package-first-pass.mjs`로 `runtime/first-pass/handoff`에 APK·서버/웹·공통 계약·소재·해시 목록을 만든다. 검수용 3001 APK를 인계본으로 오인하지 않도록 포트 확인을 넣었다. 개인 상태·SDK journal·인증값은 묶음에 포함하지 않는다. 실행 가능한 고정 시연 데이터는 서버 설정과 공통 config에 포함된다.

실행 중인 상태·SDK journal을 삭제해 새 시연을 만들지 않는다. O01로 자기 경유지 정리·현재 기기 ACK를 마친 뒤 새 회차를 연다. 실제 SDK와 모의 adapter를 전환할 때 실제 미확정·소유 경유지·복구 잠금이 있으면 서버가 거부한다.

## 실제 환경에서 추가로 보완한 사항

- 오래된 약 126MB 기록의 저장 지연이 최신 경로 표시와 SDK 실행권의 안전 시간에 영향을 주는 상황을 확인했다. 차량은 최신 조회를 먼저 표시하고 이후에도 새 승인·재조회·기존 실행권 제한을 적용한다. 서버는 검증 후 깊게 동결한 영수증/보존 기록의 JSON 바이트를 재사용한다. 전체 기록·JSON 형식·fsync/원자 교체는 유지한다. 동일 입력의 일반 저장 약 1,164ms, 보완 저장 약 229ms를 이 Mac에서 측정했으며 두 파일의 바이트가 동일했다. 이 측정은 실차 성능 보장이 아니다.
- 정상 종료가 브라우저/에뮬레이터의 유휴 연결을 기다리는 문제를 수정했다. 새 요청을 차단하고 이미 접수한 저장을 끝낸 뒤 연결과 단일 작성자 잠금을 정리한다. 대기 쓰기·유휴 연결·중복 종료 회귀를 추가했다.
- 실제 회차 5에서 추가 `applied`와 초기화용 제거 `removed`, 현재 차량 ACK를 확인해 회차 6이 열렸다. 원래 목적지 42dot와 경유지 0개를 확인했다. 실제 SDK는 추가 1회·제거 1회였다. 안전 시간 전 미실행 종료된 별도 승인들은 `not_dispatched / sdkCalls=0`으로 보존했다. 기존 11개 journal 기록은 그대로 유지하며 새 기록까지 총 16개다.
- 미확인 동안 앱 데이터를 보존한 갱신과 서버 재시작을 검수했다. 업무 초기화로 상담·선택 정보가 정리된 뒤에도 SDK/초기화 감사 기록은 보존한다. 누락된 응답을 성공·ACK로 꾸미지 않는다.

## PR #7 리뷰 후 보완 · 2026-11-13

리뷰의 확인 사항은 [3분할 내비 터치 시 음성 중단](https://github.com/ho72/wayMate/pull/7#discussion_r4559216681) 1건이다. 03·04번의 포커스 상실 시 중단 기준을 **창 포커스까지 포함**하는 것으로 명시했다. Q10의 대표 3분할에서도 순정 내비나 계기판 창을 터치하면 wayMate가 계속 보이고 RESUMED여도 음성을 멈춘다. 다시 wayMate를 터치하는 것만으로 재개하지 않으며 현재 문장 듣기를 직접 선택해야 한다. 통화 active 동의 상태나 서버 업무 상태는 창 전환으로 바꾸지 않는다. 실제 오디오 포커스 상실·앱 pause·제한 중단 정책도 유지한다.

창/수명주기 처리를 `WindowPlaybackLifecycle`로 모아 MainActivity와 기기 검수 호스트가 같은 정책을 사용하도록 했다. 서버·Repository·내비 SDK 없는 호스트에서 실제 음원을 재생하고 실제 순정 내비 창을 터치했다. 창 포커스가 사라진 동안 Activity가 RESUMED·표시 상태임을 확인하고 중단·포커스 복귀 후 무재생·명시적 재생 성공을 검증했다. 별도 pause/resume에서도 새 재생 차단·자동 재개 금지·직접 재생 성공을 확인했다.

후속 회귀는 Node **264개**, JVM **41개**, 기기 **7개(기존 5+신규 2)** 통과다. 실제/모의 APK·기기 테스트 APK 빌드와 양쪽 Lint 오류 0(각 경고 26개)을 확인했다. 위의 최초 14개 검수 중 글자 확대 7·확장 창 2는 이 후속 실행에 다시 합산하지 않는다. 실행 안내의 `verify-first-pass.sh device`도 7개로 갱신했다. [후속 검수 요약과 로그 해시](evidence/pr7-review-validation-2026-11-13.json)를 보존한다.
