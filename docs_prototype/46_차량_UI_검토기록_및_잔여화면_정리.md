## 이번에 추가로 맞춘 화면

1. 친구 소개 → 대화 고르기 → 공개 프로필 질문/답변 → 보낼 말 선택 → 답장 대기/수신/전달 완료/종료.
2. 통화 제안/동의 대기/샘플/종료/거절, 대화 쉬기/마무리/제한 안내.
3. 만남 제안/확정/취소, 이동·일정 정보 펼침.
4. 만남 경유지 추가/제거 승인, 모의 내비의 승인/처리 중/미확인.
5. 개인 경유지/새 목적지 승인, 저장 일정/같은 목적지 유지, 요청 중/성공/실패/미확인.
6. MC 별도 동의/대기/참여/거절, 정차 자막 대화 시작/대화/쉬기/종료.
7. 만남 장소로 이동/첫 만남 재연/최종 선택/제출 대기/함께·각자 여행 결과/중단·제한 안내.
8. 여행 후 기록 진입/작성/장식 반영 결과, 초기화·경유지 정리/모의 복구.
9. 계정 연결 시작/코드/계정 확인/연결 후 여행 대기/여행 수신·일정/해제/로딩·제한 안내.

## 적용 방식

- 공통 `CompanionScene`의 캐릭터 크기·위치와 2/3분할 방향을 그대로 사용한다. 기존 대화·결말의 별도 `CharacterScene`은 통합했다.
- 제목은 2분할 우측 카드 위, 3분할 가운데에 놓고 설명/상태는 같은 반투명 카드에 넣었다.
- 주요 행동은 카드 아래 큰 버튼으로 모았다. 질문·문장·최종 선택은 작은 라디오 대신 최소 96dp의 행 전체 선택을 사용한다.
- 이전은 공통 투명 버튼으로 통일하고 중복 홈 복귀·음성/일정 펼침을 정리했다. 일정·낭독·재시도·취소 등 필요한 행동은 해당 단계에 남긴다.
- 내용이 긴 메시지·일정·기록은 세로 스크롤로 이어진다. 캐릭터를 임의로 축소하거나 화면별 새 위치를 만들지 않는다.
- 일반 통화/MC/만남/최종 선택/실제 내비의 동의·승인과 미확인 요청 잠금을 합치지 않는다. 실제 SDK·마이크·계정 처리 계약을 새로 연결하지 않았다.
- 가상 개인 안내의 시연 조건 선택과 기술 목록 진입은 기본 화면에서 제외했다. Debug 미리보기의 개별 상태 진입으로 목적지 유무·성공/실패/미확인을 살펴본다.

## 캡처와 확인

추가 수정한 화면을 대기/성공/실패/거절/중단 등 **64개 상태**로 나눠 **2분할·3분할 각 64장, 기본 캡처 128장**을 남겼다. 페이지 수를 64개로 센 것이 아니라 같은 페이지의 상태를 분리한 수다.

- [2분할·3분할 캡처 목록](evidence/remaining-ui-2026-11-15/README.md)
- [두 창을 나란히 보는 전체 갤러리](evidence/remaining-ui-2026-11-15/index.html)
- 2분할 앱 영역 1682×1210, 3분할 앱 영역 841×1210. 계기판 포함 실제 Pleos 분할 창에서 PixelCopy로 앱 영역을 저장했다.
- 선택 전 전송/제출 버튼은 비활성 상태로 보여주고 선택한 항목의 action binding이 있을 때만 활성화한다. 질문·메시지·최종 선택은 행 전체를 누르며 선택 표시를 함께 보여준다.
- 긴 3분할 화면은 세로 스크롤로 이어진다. 확인 버튼이 아래에 있을 수 있으며 스크롤 뷰는 고정 이전 영역 아래에서 잘라 본문과 겹치지 않도록 했다. 기본 화면의 초기 캐릭터 배치·여백은 유지한다.

mockDebug·realDebug 빌드를 확인했다. 오프라인 Debug 호스트는 실제 계정·내비 드라이버·메시지 전송을 호출하지 않는다. 실제 정차 상태에서 가상 데이터로 프로덕션 컴포넌트를 그린 결과이며 서비스 통합 완료의 증거가 아니다. Lint·전체 기능·기기/실차 회귀는 실행하지 않았으며 [36번](36_차량_UI_검증_필요_항목.md)에 검증 필요 항목을 남겼다.

Debug에서 개별 상태를 바로 열기:

```sh
adb shell am start --user 10 --activity-single-top \
  -n com.waymate.app.mock/com.waymate.app.ui.testing.VehiclePagesPreviewActivity \
  --es headerScene batch-profile
```

다른 상태 이름은 캡처 목록의 이미지 파일명에서 `-2split.png`/`-3split.png`를 뺀 값이다. 예: `batch-meeting-confirmed`, `batch-navigation-remove`, `batch-ending-pending`, `batch-account-trip`. 실제 주행 제한은 Debug 호스트에서도 유지한다.

### 일부 조작 확인과 보충 캡처

- 3분할에서 질문 선택→물어보기 활성→해당 답변, 문장 선택→전송 전 확인→취소 후 원래 선택 유지, 가상 개인 경유지 승인→요청 중 전환을 확인했다. 실제 전송이나 내비 SDK 실행은 하지 않았다.
- [질문 선택·아래쪽 버튼](evidence/remaining-ui-2026-11-15/profile-selected-bottom-3split.png), [선택 후 답변](evidence/remaining-ui-2026-11-15/answer-from-selection-3split.png), [전송 전 확인](evidence/remaining-ui-2026-11-15/message-confirmation-3split.png), [가상 승인 후 요청 중](evidence/remaining-ui-2026-11-15/pending-after-approval-3split.png).
- [답장 아래쪽](evidence/remaining-ui-2026-11-15/messages-bottom-3split.png), [최종 선택 아래쪽](evidence/remaining-ui-2026-11-15/ending-pending-bottom-3split.png), [기록 아래쪽](evidence/remaining-ui-2026-11-15/review-write-bottom-3split.png), [계정 일정 아래쪽](evidence/remaining-ui-2026-11-15/account-trip-bottom-3split.png)에서 스크롤 후 버튼 도달과 고정 이전 영역 분리를 확인했다.
- 후속 UIAutomator 조회가 이전 화면의 노드를 반환해 내비 버튼 자동 탐색은 중단됐다. 현재 화면과 수동 전환은 네이티브 캡처로 확인했으며 자동 회귀 통과로 기록하지 않는다. 장식 재반영·날짜 넘김 조작은 미실행이다. [일부 조작 기록](evidence/remaining-ui-2026-11-15/ui-checks.json).

계기판을 포함한 전체 배치도 [2분할](evidence/remaining-ui-2026-11-15/intro-2split-device.png)·[3분할](evidence/remaining-ui-2026-11-15/intro-3split-device.png)로 남겼다.
