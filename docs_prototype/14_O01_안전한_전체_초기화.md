# O01 안전한 전체 초기화

2026-11-12. 기준은 03번 O01, 04번 §5.3·§9.3, 05번 Q14다. `docs_proposal`은 변경하지 않았다. 이번 구현은 현재 v4에 존재하는 상담·공개·매칭·전달·만남·실제 내비의 전체 초기화다. O01의 다른 콘텐츠 제어와 최종 재시연, Q14의 모든 모드, Q28 전체 완료를 뜻하지 않는다.

## 동작과 실행

`mock-app`에서 Node 22.22.2로 `npm start`를 실행한다. 모바일은 `/`, 시연자는 `/operator`다. O01의 **처음부터 시작 → 초기화 시작**을 누르면 현재 회차를 잠그고 `resetId`를 발급한다. 현재 회차와 SDK 기록을 먼저 지우거나 새 회차를 미리 열지 않는다.

| 현재 회차 | 완료 조건 |
|---|---|
| 아직 웹만 사용 | 그 회차를 소유한 브라우저가 대화·입력·소개 초안·일반 대기 요청을 정리하고 웹 ACK |
| 차량에서 불러오기/직접 시작 완료 | 실행한 동일 `deviceId`의 현재 세션이 차량 화면·대기 요청을 정리하고 차량 ACK. 닫힌 모바일 ACK는 기다리지 않음 |
| 실제 내비 시도 이력 있음 | 미확정 시도 없음, 소유 경유지 없음, 원래 D와 기준 경유지의 실제 이중 관측, 종료된 SDK journal과 보고 ACK까지 확인 |
| wayMate 경유지 남음 | 차량 초기화 화면에서 **초기화를 위한 경유지 제거 승인 → 승인하고 제거**. 정차·전경·최신 제한/경로 검증 후 자기 경유지만 제거 |
| unknown·충돌·정리 증빙 부족 | 잠금과 대기 이유 유지. 파일 삭제나 임의 성공 처리로 통과시키지 않음 |

내비 SDK 실행으로 순정 내비가 전면에 나오면 wayMate로 돌아온 뒤 차량 정리를 마친다. 전경 상태가 아닌 동안 차량 ACK를 보내지 않는다. ACK가 끝나면 서버가 한 번의 원자적 저장으로 `runSeq+1`·새 `runId`를 발급하고 온보딩·프로필·공개·여행·연결·만남·전달 상태를 비운다. 차량은 새 세션/상태 보고부터 시작한다. 닫혀 있던 모바일도 나중에 접속하면 완료된 이전 회차의 초안과 대기 요청을 정리한다.

## 계약과 보존

`handoff-v4.schema.json`에 `RESET_BEGIN`, 웹/차량 `RESET_ACK`, 초기화 projection·보존 기록과 `reset_cleanup` 대상을 추가했다. 기존 v4 저장 파일의 새 필드는 선택 사항이며 v2/v3 파일·계약은 바꾸지 않는다. 새 예제는 실제 coordinator로 생성한다.

- 제거 명령은 `reason=reset_cleanup`, 현재 `resetId`, 원래 소유 add attempt를 참조한다. 만남이 confirmed여도 허용하며 정리를 위해 cancelled로 조작하지 않는다.
- ACK는 같은 장치의 현재 세션/epoch에 묶인다. 이전 세션·다른 장치·오래된 관측·미처리 요청·남은 소유권·제한 상태를 거절한다. 실제 작업 이력이 있으면 실제 source와 journal을 요구한다.
- 차량의 SDK journal은 회차 밖에 보존한다. 서버는 종료 회차의 내비 시도·관련 NAV/RESET 영수증·ACK를 보존하고 온보딩 원문/프로필 초안은 보존 기록에 복사하지 않는다. 미처리 사실은 정리하지 않은 채 버리지 않는다.
- 같은 요청 재전송은 기존 영수증만 반환하며 실행권을 재발급하지 않는다. 이전 업무 명령은 새 회차를 바꾸지 못한다. 알려진 이전 SDK 실행의 늦은 보고는 별도 사실로 남기고 현재 경로와 충돌하면 recovery로 잠근다.
- 누적 영수증 때문에 최신 상태 검증이 지연되는 문제를 확인했다. 모든 영수증을 유지하면서 깊게 불변화한 개별 영수증/완료 기록의 검증만 캐시한다. 현재 업무 상태는 계속 검증하며, 교체·변조된 기록은 다시 검증한다. TTL·운전자 승인·실행권 기한은 완화하지 않았다.

웹은 현재 v4 회차의 초안만 지우고 다른 앱이나 v2/v3 키를 지우지 않는다. 시연자의 초기화 outbox는 B 응답 outbox와 분리해 미확인 B 요청이 있어도 초기화를 시작할 수 있다. 응답 유실·GET 실패는 초기화 명령 ID/본문을 유지하고 영수증으로 복구한다. 차량은 승인하지 않은 실행권을 버리되 실제 실행/보고는 보존·대사한다. 승인 대화상자는 검토한 경로와 resetId에 묶인다.

## 실제 Pleos 검증

Pleos Connect 2.1.0/API34, 사용자 10, `com.waymate.app.real`에서 검증했다. 실제 D는 `42dot`, 실제 M은 독립 POI 조회한 `소프트웨어드림센터`다. 가상 강릉 카페·ETA를 실제 검증한 것으로 설명하지 않는다. 회차 2의 프로필·매칭·만남 제안과 B 수락은 API fixture로 준비했다. 차량 불러오기, 네이티브 운전자 승인, SDK 추가/제거, O01 초기화와 차량 ACK는 실제 앱/서버에서 실행했다.

1. 기존 경유지 정리가 끝난 회차에서 차량 앱을 닫고 초기화했다. 모바일도 닫힌 상태에서 같은 회차로 차량 ACK를 기다렸다. 재접속 후 D 유지/경유지 없음·기존 journal 확인으로 새 회차가 열렸고 journal 파일은 전후 바이트까지 같았다.
2. 새 회차에서 실제 M을 1회 추가했다. 앞선 승인은 실행되지 않은 `not_dispatched`, SDK 호출 0회로 보존했다. 새 승인으로 추가 성공을 확인했다.
3. 만남 confirmed·M 소유 상태에서 O01을 시작했다. 같은 run/resetId와 M이 유지됐고 새 업무가 잠겼다. 차량 강제 종료·최종 APK 데이터 보존 재설치·재실행 후 같은 기기의 새 세션/epoch가 정리를 이어받았다. 이때 journal은 추가 전후 동일했고 자동 SDK 호출이 없었다.
4. 차량에서 별도로 제거를 승인했다. `reset_cleanup` remove SDK 호출 1회로 M이 제거됐으며 D는 유지됐다. 제거 이후 차량 전경 복귀와 현재 이중 관측·보고/journal ACK를 확인하고 차량 ACK가 적용됐다. 마지막까지 만남은 confirmed였고, 전체 초기화 완료 때 새 회차의 none으로 비워졌다.
5. 회차 2→3 전환 후 온보딩·프로필·여행·공개·전달·연결/만남이 초기 상태이며 M 소유권이 없다. 기존 SDK 기록은 모두 남아 있다.
6. 기존 버전에서 회차 식별값 없이 저장한 초안이 남는 경우도 실제 복귀에서 확인했다. 서버의 완료 회차 목록으로 본인의 이전 v4 초안을 모두 정리하도록 보완했고, 실제 재접속에서 남은 키가 없음을 확인했다. 현재 회차와 다른 클라이언트의 초안은 보존하는 회귀 시험을 추가했다.
7. 별도 웹 전용 회차에서 답변 저장과 미전송 초안 입력 후 O01을 실행했다. 소유 브라우저 ACK 후 새 회차로 전환됐고 v4 draft/pending 키는 없었다. 새로고침 후 빈 상담 첫 질문을 확인했다.

## 회귀 테스트와 남은 범위

Node 22.22.2 전체 **147개**, Kotlin 정책 **21개** 통과. mockDebug/realDebug APK와 두 Android Lint 통과. Lint는 각각 오류 0·경고 20이며 의존성 갱신 안내와 기존 항목, SharedPreferences KTX 권고를 포함한다. 무경고로 기록하지 않는다. v4 예제 생성은 두 번 실행해 동일함을 확인했다.

회귀 시험은 원자적 전환·필수 ACK·같은 장치 재접속·confirmed 만남 정리·미확정 실행·늦은 SDK 보고·중복 실행권 방지·잘못된 ACK/증빙/제한·기록 변조·응답 유실·새로고침·여러 번 초기화 뒤 복귀를 다룬다. Android는 ACK 잠금·이전 승인 거절·journal scope·초기 상태의 null 처리·관측 요청 중 사용자 승인 보존 정책을 검사한다.

등록된 복구 절차와 `RECOVERY_CONFIRM`, 모의 `NAV_MOCK_RESULT`, 아직 없는 콘텐츠/통화/음성 재생 종료·결말·최종 재시연은 구현 완료로 표시하지 않는다. unknown은 계속 잠그며 실제 실패를 임의 주입해 복구한 것으로 주장하지 않는다. 실차·실제 주행·전체 Q14·Q28과 가설 V 검수는 미완료다.
