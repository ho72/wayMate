# v4 화면 전환과 연결 구현

기준: docs_prototype 01~04 v0.8, 08 v0.4. docs_proposal은 구현 기준에 사용하지 않는다. 기존 07·10~12와 v2/v3 계약·상태·SDK 이력은 보존한다.

## 먼저 수정할 구조

| 현재 구현 | 개정 문서 기준으로 수정 |
|---|---|
| 모바일 한 페이지에서 답변·소개·여행·전달 | M01 대화/소개 → M02 여행 → M03 공개 확인/추천 → M04 요청·B 수락·공통 시간 최종 확인 → 전달 준비 |
| 차량의 동행 추천 준비 중 버튼 | 제거. 차량에는 신규 후보·매칭 명령 없음 |
| 차량 본인 여행만 전달 | v4 connected/my_trip을 분리하고 최초 수신 때 공개·연결·core 버전을 검증 |
| 차량의 일반 내비 시험 화면 | P03의 장소/시간 검토 → A 제안 → 동일 제안 B 수락 → 운전자 내비 승인으로 연결 |
| 내비 추가/제거와 만남 상태 독립 | 취소는 즉시 기록. 늦은 추가 성공은 만남을 되살리지 않고 제거 필요로 유지 |
| 작은 홈 일정 요약 | connected/my_trip 모두 큰 내 친구와 저장된 계획·다음 일정·숙소 예상/마감을 기본 홈에 지속 표시 |

‘모바일 최종 매칭 확인’은 M04의 공통 시간 확인(CONFIRM_WINDOW)이다. 만남 이후의 최종 동행 선택(P04)은 별도 단계이며, 문서의 A/B 독립 동시 제출 설계를 유지한다. 이번 작업은 모바일 매칭·전달과 차량 만남 동의·실제 내비 승인 연결을 구현한다. 통화·MC·음성·만남 후 최종 선택·전체 초기화는 완료로 표시하지 않는다.

v4는 새 상태 파일과 새 웹 outbox/초안을 사용한다. v3 파일을 변환하거나 기존 SDK 실행 이력을 지우지 않는다. 물리 내비는 기존 검증 장소를 별도 시험 좌표로 사용한다. 가상 바다쉼표 카페·강릉 ETA와 실제 소프트웨어드림센터의 위치/경로를 동일한 것으로 표시하지 않는다.

## 실행·보존

`mock-app`에서 Node 22.22.2로 `npm start`를 실행하면 v4 서버(`runtime/state-v4.json`)가 열린다. 모바일은 `/`, 시연자는 `/operator`다. 시연자는 현재 연결·만남 요청에만 B 수락/거절/취소를 지정한다. 상대 응답은 자동 타이머로 생성하지 않는다. 기존 v3는 `npm run start:v3`, 별도 기존 상태 파일과 `web/legacy-v3`로 보존한다. v2/v3 계약·예제는 수정하지 않는다.

v4 웹은 별도 pending/draft 키를 사용한다. 미확인 연결 생성 요청의 취소도 자체 outbox를 저장하고 영수증으로 복구한다. v4 차량은 새 통신 outbox를 사용하되 기존 기기 ID·물리 SDK journal은 유지한다. 이전 회차의 제거 완료·확인 기록이 있는 경우에만 새 상태로 진행하며, 소유 경유지나 미확인 실행 기록이 남으면 잠근다. 서버/앱 재시작·화면 복원은 SDK 호출을 재구성하지 않는다.

`CANCEL_PENDING_COMMAND`는 원래 commandId에 취소 기록을 남겨 아직 도착하지 않은 요청도 뒤늦게 실행되지 않게 한다. 이미 적용된 만남/연결은 원래 commandId가 현재 대상을 생성한 요청과 일치할 때만 취소한다. 내비 승인 요청의 취소는 만남 동의를 변경하지 않는다. 실제 내비가 호출됐거나 실행 여부가 불확실하면 경유지 제거 성공으로 기록하지 않으며, 늦은 실제 추가는 취소 상태와 정리 필요를 유지한다.

## 파일 경계

- `shared/contracts/handoff-v4.schema.json`, `shared/examples/v4`: 새 계약과 실제 coordinator로 생성한 예제.
- `server/v4`: 역할·모바일 매칭·전달·만남·실제 내비 승인. 기존 원자적 저장 도구 재사용.
- `web/app.js`, `web/shared/client-v4.mjs`, `web/operator.*`: 대화 중심 모바일 화면과 현재 요청 응답 패널.
- 차량 `SocialUiState`/`MeetingScreen`: 표시·운전자 의도. Repository는 HTTP/영수증/복원을 담당하고 기존 real NaviHelper adapter가 실제 변경을 실행한다.

현재 지원은 고정 B 후보 연결과 고정 장소·시간의 만남 제안이다. 바다쉼표 카페는 가상 시연 장소이고, 실제 내비는 독립 검증한 소프트웨어드림센터를 사용함을 승인 화면에 표시한다. 실제 강릉 카페 검색이나 강릉 ETA 검증으로 설명하지 않는다. 전체 대화 콘텐츠·통화/MC·주행 음성·만남 종료 후 P04 동시 선택·일반 장소 검색·O01 전체 초기화는 후속이며 완료로 표시하지 않는다.

## 모바일 대화 화면 보정 (2026-11-11)

M01의 중심을 누적 대화 기록과 하단 고정 자유 입력창으로 맞췄다. M01~M04의 상태·명령 경계는 유지하며, 화면은 한 대화 안에서 소개·여행·공개·연결 카드가 이어진다. 준비 중 이전 내용 확인은 접힌 `내 여행` 메뉴에서 연다.

- 질문을 한 번에 하나씩 제시하고 원문 답변을 말풍선에 보존한다. 예시는 직접 전송하지 않고 초안만 채운다.
- 네 가지 자유 답변 뒤 별명·캐릭터 카드와 소개 확인 카드를 순서대로 표시한다. 추가 소개 선택은 기본으로 접고, 미선택 항목은 빈 값으로 유지한다. 원문에서 성향을 자동 추론하지 않는다.
- 소개 저장·소개 공개·여행 요약 공유·모바일 최종 매칭 확인은 각각 기존 명령과 명시적 확인을 유지한다. 차량 만남/내비 명령은 변경하지 않는다.
- 대화 초안 외에 미확정 별명·캐릭터·직접 고른 소개 항목·카드 단계를 회차와 답변 revision에 묶어 로컬 보관한다. 새로고침은 자동 전송하지 않는다.

응답 문장은 정해진 프로토타입 시나리오다. 자유 생성 AI 상담·답변 의미 분석·자동 요약이 구현된 것으로 설명하지 않는다.

430×932 실제 브라우저에서 네 자유 답변, 누적 말풍선, 입력 중 새로고침 복원, 별명/소개 카드 단계 복원, 직접 고른 소개 저장, 여행 저장, 별도 공개 검토를 확인했다. 기존 Node 계약/통합 테스트 100개가 통과했다. 이번 변경은 웹 표시와 로컬 초안 관리에 한정되며, 기존 실 SDK 검증을 재실행한 것으로 기록하지 않는다.


## PR #2 리뷰 수정과 회귀 검증 (2026-11-11)

리뷰의 기능/문구 6건과 정리 3건을 다음과 같이 반영했다. 기존 v4 계약·enum·실제 SDK adapter는 변경하지 않는다.

| 지적 | 수정 |
|---|---|
| 내비 승인 취소가 만남까지 취소 | NAV_APPROVE 취소는 해당 attempt의 실행 전 승인만 중단. 양쪽 만남 동의 유지. 이미 dispatch된 사실·결과·경유지 소유권을 지우지 않음 |
| 미도착 제안 취소가 다른 만남을 덮어씀 | 원래 commandId의 취소 표식만 저장. 이미 존재하는 다른 proposed/confirmed 만남과 동의는 유지. 아직 첫 제안이 없는 경우의 취소 표식/회차 잠금은 유지 |
| stop POST 확정 거절 뒤 동기화 반복 실패 | StopCommandOutbox가 POST 400~500의 확정 거절만 종료. GET 실패·POST 타임아웃/503은 같은 ID·본문을 보존하고 영수증으로 복구 |
| 미확인 일반 요청 때문에 만남 취소/연결 종료 차단 | 만남 취소·연결 종료·공개 철회를 별도 durable stop 경로로 전송. 일반 요청은 별도로 보존하며, 원래 ID를 명시 취소한 성공에만 해당 일반 pending을 해제 |
| 운영자 GET 실패로 미확인 B 응답 유실 | GET 실패는 pending 보존. 해당 POST의 확정 거절에만 종료. 응답 유실 뒤 영수증으로 복원하며 재전송은 같은 본문/ID |
| 미확인 요청 취소 대화상자 문구 | 별도 제목과 NAV_APPROVE/MEETING_PROPOSE별 설명. 내비 승인 취소와 만남 동의·물리 제거의 차이를 표시 |
| 실행되지 않는 PROFILE_PRIVATE 분기 | handoff의 중복 분기 제거. 공개 필드를 비우는 social 처리만 사용 |
| 웹의 전달 모드 직접 계산 | 두 전달 버튼 모두 서버의 HANDOFF_PREPARE binding으로 전송 |
| v3 client 복사본 미사용 | v3 정적 /shared/client.mjs가 보존된 legacy-v3/client.mjs를 제공하도록 연결. 기존 파일/계약 삭제 없음 |

동일 원칙을 미도착 CONNECT_REQUEST 취소에도 적용해 무관한 기존 연결을 종료하지 않는다. 취소된 원래 명령의 늦은 도착은 계속 차단한다.

추가 회귀 테스트는 Node 16개(서버 8·운영자 8), Kotlin outbox 6개다. Node 전체 116개와 Kotlin 전체 15개가 통과했다. 새 서버/운영자 테스트를 수정 전 fc210b2 코드와 격리 대조하면 28개 중 9개가 실패하고, 수정 후에는 모두 통과한다. Android mockDebug/realDebug APK 및 두 Lint는 통과했으며 각각 오류 0·경고 18이다. 생성 계약 예제는 변경 없이 일치한다.

기존 v4 상태로 서버를 재시작하고 real APK를 데이터 보존 업데이트해 내 친구·여행·연결 홈 복원을 확인했다. 같은 run과 기존 취소된 만남을 유지했고, 내비 attempt는 2개·owned=null로 유지됐다. SDK journal의 업데이트 전후 SHA-256이 동일하다. 이번 수정 검증에서 실제 경유지 추가/제거를 다시 호출한 것으로 표시하지 않는다. 통신 실패는 서버 통합/운영자 스크립트/Kotlin outbox 테스트로 검증했으며, 실차나 실제 SDK의 오류 주입 검증을 수행한 것은 아니다.

[검증 요약](evidence/pr2-review-fixes-2026-11-11.json)에 테스트·빌드·기존 상태 보존 결과를 기록한다.
