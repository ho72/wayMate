# 답장 확인: 정차·주행 표현과 캐릭터 음성 상태

2026-11-15. 기존 두루밋 헤더·반투명 카드·큰 버튼·2/3분할 구성을 유지했다. [캡처 갤러리](evidence/reply-voice-2026-11-15/index.html).

## 반영 범위

- 정차: 내가 보낸 말, 상대 답장, 후속 질문, 전체 행 선택을 하나의 카드에 배치. 선택한 뒤 **답변 확인 → 수신자·문장 재확인 → 확인하고 전송**으로 기존 명령 binding을 사용한다. 선택만으로 전송하지 않는다. 주 행동 두 개는 나란히, 한 개는 가운데 정렬한다.
- 주행용 UI: 현재 답장·질문·읽기 전용 선택지 두 개로 압축. 라디오·선택·전송 버튼과 이전 버튼을 제거했다. 짧은 음성 안내 문구는 카드 바로 아래에 배치한다.
- 실제 제품에서 주행 중 사회적 메시지 노출은 기존 `DrivingScreen` 제한을 유지한다. 주행용 답장 표현은 **실제 정차 상태에서만 진입 가능한 Debug 호스트**에서 제공한다. `DrivingModePolicy`, 메시지 정책, 음성 allowlist를 완화하지 않았다. 이 캡처의 ‘주행 중’ 헤더는 그 표현을 검토하기 위한 가상 상태다.
- 정차 제품 화면의 말하기·준비·중단·사용 불가 표시는 기존 `SpeechState`와 연결한다. **듣기/인식 처리 표시는 Debug 시연만 존재**하며 화면에 ‘음성 UI 시연 · 마이크 꺼짐’을 표시한다. 실제 마이크·STT·자유 발화 전송은 추가하지 않았다.
- 읽음 처리, 여러 스레드 선택, 대기/전달/종료, 미확인 전송의 결과 확인·취소, 기존 최종 전송 확인은 유지한다. 답장 스레드/상태가 달라지면 선택과 확인 패널을 비운다.

## 캐릭터 중심 그래픽

| 상태 | 캐릭터 위 공통 표시 | 캐릭터 주변 그래픽 | 의미 |
| --- | --- | --- | --- |
| 말하기 | 스피커 + 답장을 읽고 있어요 | 몸 바깥의 작은 5막대 파형 | 에이전트 출력 |
| 듣기 | 마이크 + 듣고 있어요 | 양옆 열린 곡선 + 작은 마이크 배지 | 입력 세션. 현재는 시연이며 마이크 꺼짐 고지 |
| 인식 처리 | 모래시계 + 말씀을 확인하고 있어요 | 몸 바깥의 세 점 | 발화 해석 대기. 현재 시연 |
| 대기 | 말풍선 + 대화 대기 | 추가 효과 없음 | 마이크가 열렸다는 의미가 아님 |
| 대화 쉼 | 일시정지 + 대화를 쉬고 있어요 | 파형/입력 곡선 제거 | 향후 입력·출력 세션 쉼 계약 |
| 낭독 준비/중단/불가 | 각 상태에 맞는 아이콘·문구 | 입력 그래픽 없음 | 실제 기존 출력 상태 |

기존 곰 캐릭터 원본은 수정하지 않았다. 캐릭터 몸·얼굴은 움직이지 않고 기능 그래픽만 사용한다. 정차에서는 작은 파형 높이와 듣기 곡선의 불투명도/처리 점만 천천히 변한다. 이는 입모양 동기화나 실제 입력 음량 측정이 아니다. 주행용 UI는 모두 정적이며, 시스템 애니메이션 비활성/창 포커스 상실 때도 정적으로 표시한다. 색 외에 아이콘과 문구로 의미를 함께 전달한다.

배지 위치는 두 분할에서 동일하게 캐릭터 주변에 붙이며 3분할에서는 48dp, 2분할에서는 64dp로 표시해 몸을 가리지 않는다. 상태 문구는 하나의 정중한 접근성 알림 영역이고 장식 파형·곡선은 중복 읽기를 제거한다.

## 향후 실제 음성 흐름 계약 — 아직 연결하지 않음

1. 대화 시작 의사와 플랫폼 허용 상태를 확인한 뒤 현재 답장·질문을 읽는다. 메시지 수신만으로 마이크를 열지 않는다.
2. 읽기 완료 후 입력 세션이 실제로 열렸을 때만 듣기 표시. 실제 수음 레벨은 향후 입력 곡선/미터와 연결한다.
3. ‘첫 번째’ 또는 문장 발화를 해석한다. 처리 중에는 마이크 표시를 끄고 세 점으로 전환한다.
4. 수신자와 보낼 문장을 다시 읽는다. ‘보내줘’라는 별도 승인 뒤에만 최신 binding으로 전송한다. 실제 ACK 전 전달 완료를 표시하지 않는다.
5. 무응답/취소/실패/포커스 상실/주행 제한 변경 시 입력·출력을 닫는다. 복원·정차 복귀 시 자동 재생·전송하지 않는다.

‘안내 멈추기’는 현재 출력 중단, ‘대화 쉬기’는 향후 입력·출력 세션 쉼으로 의미를 구분한다. 이번 제품 UI에는 기존 출력 중단만 연결했다.

## 확인 및 미확인 범위

빌드·오프라인 캡처와 디자인 리뷰 결과는 작업 완료 후 아래에 기록한다. 실제 음성 인식·실차·차량 정책·접근성 실행은 [검증 필요 문서](36_차량_UI_검증_필요_항목.md)에 별도로 남겼다. 화면 캡처는 통합 기능 검증 결과가 아니다.

### 빌드·표시 확인

- `assembleMockDebug`, `assembleRealDebug`, `compileMockDebugAndroidTestKotlin --offline` 성공. 기기 테스트 실행 통과를 의미하지 않는다.
- 정차 Debug 호스트에서 정차/주행용 × 말하기/듣기/처리/쉼/대기 × 2/3분할 20장, 실제 `ContentScreen`의 받은 답장/대기/전달/종료 × 2/3분할 8장, 합계 28장을 캡처했다. 전체 PNG 청크·CRC·IEND·zlib·크기(1682×1210 / 841×1210)를 확인했다.
- 실제 정차 Debug 2분할에서 첫 답변 행 선택 → 답변 확인 → 수신자·문장 확인 패널 → 돌아가기 취소 후 같은 선택 유지까지 네이티브 화면으로 확인했다. [확인 패널](evidence/reply-voice-2026-11-15/interaction/reply-confirm-2split.png), [취소 후 복귀](evidence/reply-voice-2026-11-15/interaction/reply-cancel-2split.png). 실제 전송·ACK·서버·마이크는 실행하지 않았다.
- 이전 전체 HTML 갤러리 두 곳에는 이번 답장·음성 상태 갤러리로 이동하는 최신 링크를 추가했다. 과거 캡처를 현재 버전으로 오인하지 않도록 기존 기록은 유지했다. GitHub push/PR은 이번 작업에서 하지 않았다.

### 디자인 리뷰 결과

차량 UI 디자이너 관점의 서브에이전트가 최신 원본28장을 모두 확인하고 **시각·배치·상태 의미 OK**로 최종 컨펌했다. 1차에서 상태 배지의 몸 겹침·정차3분할 카드 여유·주행 안내 위치·처리/중단 문구를 수정했고, 실제 제품 연결8장에서는 고지 잘림과 답장 없는 상태의 선택 안내를 추가 수정했다. 추가 필수 수정 사항 없음. 실제 음성 입력·제품 주행 허용·기능/실차 검증은 리뷰 범위에 포함하지 않는다.
