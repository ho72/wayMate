# 모바일 실제 에이전트 서비스

2026-11-14 · 후속 요청: “모바일도 실제 서비스처럼”, 범위 확인: **실제 사용 기능까지 구현, 공개 배포는 이후**.

## 이번 개정 범위

기존 M01~M04의 고정 시연 순서를 실제 개인 서비스의 사용 흐름으로 확장했다. `service/`는 본인 계정·대화·취향·여행을 독립 저장한다. 기존 v4 시연의 역할 헤더나 준비된 B의 응답을 실제 사용자 인증/상대 통신으로 사용하지 않는다. 31번의 캐릭터·하늘색/민트·흰 카드·큰 버튼 계통을 이어가되, 운영자 제어와 시연 단계 이동은 사용자 웹에 넣지 않는다.

| 화면 | 실제 동작 |
|---|---|
| 홈 | 내 계정·캐릭터·저장 여행·확정 취향 표시. 대화 시작 예시는 수정 가능한 입력 초안이며 자동 전송하지 않음 |
| 계정 | 아이디·별명·비밀번호 가입, 로그인·로그아웃. 비밀번호 해시와 서버 세션 사용 |
| 대화 | 자연스러운 자유 입력, 실제 스트리밍, 대화별 기록·진행 상태·중단·명시적 재시도 |
| 취향 후보 | AI가 요약한 내용을 본인이 확인해 기억. 직접 수정한 최신 프로필과 충돌하면 덮어쓰지 않음 |
| 여행 초안 | 목적지·기간·일별 장소·메모를 실제 도구로 제안. 확인 버튼 전에는 저장 여행 목록에 없음 |
| 내 여행 | 직접 저장한 여행 목록·날짜별 상세·네이버 지도 검색 링크 |
| 마이 | 별명·취향·소개·파도/모카 변경, AI 전달 동의 철회 |
| 대화 기록 | 진행 중/보관함·복원. 생성 중 보관 불가, 보관한 대화에 새 전송 불가 |

확정값처럼 보이는 가짜 여행·가짜 사람·가짜 전송 성공을 넣지 않았다. 홈의 추천 시작 문구는 AI 답변이 아니라 입력 보조다. 새 사용자는 여행 목록이 비어 있다.

## 에이전트의 실제 권한

OpenAI Responses와 `store:false`·함수 호출을 사용한다. 본인 취향 읽기(`get_profile`), 본인 여행 읽기(`get_saved_trips`), 일정 초안 제안(`propose_trip`), 취향 후보 제안(`propose_preferences`)을 제공한다. 사용자 ID는 모델 인자가 아니라 인증 세션에서 결정한다.

모델 입력과 반환값 모두 JSON 스키마·날짜/시간·일정 순서를 검증한다. 초안은 응답이 정상 완료돼야 저장되고, 확정 프로필/여행으로 옮기는 일은 별도 HTTP 확인에서 원자적으로 처리한다. AI가 저장했다고 말하기만 해서는 확정되지 않는다. 중복 확인은 같은 저장 결과를 반환한다.

대화 원문은 외부 요청 전에 먼저 DB에 남긴다. 네트워크가 끊긴 전송은 같은 요청 ID·원문·버전을 다시 제출해 기존 결과를 확인한다. 실패나 서버 재시작 후 자동 유료 재생성을 하지 않는다. 재시도는 최신 실패/중단 메시지에서 직접 선택한다. 로그아웃·동의 철회 후 늦게 도착한 생성 결과나 다른 계정의 늦은 브라우저 응답을 반영하지 않는다.

실시간 장소 검색·영업 여부·교통·날씨·예약 도구는 없다. 생성한 일정은 방문 아이디어이며 장소와 운영 정보는 지도에서 다시 확인한다. AI 동의 화면에는 대화와 저장 취향/여행이 OpenAI에 전달됨을 명시한다.

## 실행·개발 책임

[서비스 README](../service/README.md)에 실행, 환경변수, API, 데이터 백업과 lock 복구를 정리했다. Node 22.22.2, 3004번 로컬 서버, 별도 SQLite 파일을 사용한다. 서버 전용 키는 기존 `mock-app/.env`를 읽거나 서비스 전용 `.env`로 지정한다. 두 DB·쿠키·명령 계약을 섞지 않는다.

- 웹: `service/web/`, 채팅·메뉴·입력·저장 상태·접근성·반응형.
- 서버/AI: `service/server/`, 공통 schema·소유권·세션·저장·모델 도구·중단/복구.
- 검증: `service/tests/`, 새 CI `service-checks.yml`. CI는 외부 API 키나 실제 과금을 요구하지 않는다.
- 차량: 기존 `mock-app/vehicle/`와 SDK 실행권/journal을 유지한다. 이 변경에서 차량 코드를 바꾸지 않았다.

## 다음 통합의 경계

개인 AI 상담과 여행 저장은 실제 기능이지만, 새 계정↔차량 페어링과 동적 일정 전달은 후속이다. 기존 v4는 고정 시연 장소·일정·공개/독립 선택 계약을 사용하므로 새 DB를 v4에 자동 복사하면 안 된다. 본인/차량 인증 → 확정 여행 요약 → 좌표/POI 검증 → 운전자 승인 → 실행권·journal·ACK 순서로 별도 계약을 확장해야 한다.

실제 사용자 간 추천/매칭·상대 음성 통신, 음성 입력/출력, 계정 복구·삭제·내보내기, 운영 모니터링과 공개 배포도 후속이다. 기존 시연의 가상 B나 샘플 통화를 새 서비스의 실제 기능으로 표시하지 않는다.
