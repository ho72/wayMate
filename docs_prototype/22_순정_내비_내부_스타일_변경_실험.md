# 순정 내비 내부 스타일 변경 실험

2026-11-12. 사용자가 요청한 대로 기존 환경을 유지하고 별도 AVD에서 내부 스타일 변경을 시험했다. **내부 메서드는 호출·반환됐지만 도로 지도 표시에는 성공하지 못했다.** 교체 시도 뒤 순정 내비의 경로 화살표 레이어 누락 예외와 재시작을 관찰했다. 공식 설정이나 제품에 적용할 해결책을 확보한 결과는 아니다.

## 실험 환경과 보존

- 기존 `emulator-5554`에는 읽기 전용 조회만 했다. 실제 SDK journal 11개 기록은 전후 SHA-256 `6e2c95eaf39cacbc5c6cf7fb490de78f75806ca9465613e88e711dbaea5c7f84`로 동일하다. 순정 내비 PID도 기존 확인값 10257이다.
- 별도 `WayMate_Native_Map_Probe` / `emulator-5556`에서 실행했다. Pleos 2.1.0 ARM64, Emulator 37.2.13, host GLES·Vulkan 비활성 조건이다. wayMate 앱이나 실제 서버 명령을 실험에 사용하지 않았다.
- 일반 배포 빌드는 디버그 접속이 제한돼 **공유 SDK 이미지의 독립 APFS 복사본**에서만 init/CIL 디버그 조건과 로컬 진단 서비스를 구성했다. 직접 호출 시험 당시 별도 AVD의 SELinux는 Permissive였다. **순정 내비 APK는 변경하지 않았다.** 기본 환경과 다른 실험 조건임을 결과 해석에 포함한다.
- 공유 원본의 init.rc·CIL·정책 해시 해당 영역은 원래 내용과 일치하고, 원본 ramdisk SHA-256도 유지됐다. 전체 17GB 이미지의 전후 해시를 새로 계산했다는 의미는 아니다.
- 종료 후 별도 AVD는 정지했고 비교 AVD config를 백업과 바이트 동일하게 복원했다. 임시 디버그 앱 설정·포트 전달도 정리했다. 원래 실행 스크립트는 변경하지 않았다. 메일·외부 문의·게시판 작성은 하지 않았다.

## 실제 호출과 관찰

상위 `NavigationUseCase.setMapStyle`가 repository를 거쳐 최종 위임하는 **순정 앱 내부 SDK의 `ai.umos.maps.android.navigation.sdk.manager.MapManager.setMapStyle(String)`**를 메인 스레드에서 호출했다. 공개 NaviHelper API에 이 기능이 추가된 것이 아니다.

1. 내부 지도 객체를 읽어 현재 URI가 `connect_empty`, 로드 상태 true, 레이어 4개·소스 1개·도로 이름 레이어 0개임을 확인했다. 카메라는 시뮬레이션 위치 `[127.094681, 37.4127212]`, zoom 16.5였다.
2. 인증값 없이 공개 `connect_v2` 스타일을 조회했다. HTTP 200, 레이어 263개·소스 17개였고 ID에 road/도로/고속이 포함된 레이어는 32개였다. 이 숫자는 이름 기반 집계이며 전체 도로 레이어의 의미적 분류는 아니다. transport 타일 메타데이터도 HTTP 200이었다. 실제 모든 타일 수신·렌더링 성공을 뜻하지 않는다.
3. 같은 빈 스타일을 지정하는 대조 호출과 `https://a.tile.static.maps-coral.umos.ai/styles/42dot/connect_v2` 지정 호출은 모두 반환됐다. **void 메서드의 반환과 스타일 로드 완료·화면 표시·SDK ACK는 구분한다.** 대조 호출 후 정상 렌더링까지 통과한 것으로 계산하지 않는다.
4. 도로 스타일 교체 시도 뒤 캡처는 내비 실행 중 화면이었고, 순정 프로세스 로그에는 아래 예외가 있었다. 이후 안정적으로 로드된 `connect_v2` 상태나 도로 표시는 확인하지 못했다.

```text
com.mapbox.maps.MapboxStyleException:
Add layer failed: Cannot find layer with id: TRIP_ROUTE_ARROW_HEAD_SYMBOL_LAYER
```

스택은 `MapManagerOverlayExtensionKt.addPolyline → MapManager.addMap42Manager → Navi42MapView.onMapReady`의 오버레이 초기화 경로를 가리킨다. **실행 중 URL만 교체하면 충분하다는 가정은 이번 시험에서 성립하지 않았다.** 디버그 권한 변경·Java bridge 오류·초기화 타이밍이 개입했으므로 해당 예외의 유일한 원인이나 일반 배포본 결함으로 확정하지 않는다.

초기 지도 로드부터 빈 URL을 바꾸는 추가 비교도 시도했으나 Java helper 실행 오류와 spawn-gating 연결 단계 때문에 hook-ready·스타일 상태 증빙을 확보하지 못했다. 이 방식은 **미검증**이며 도로 표시 실패로 판정한 별도 기능 시험이 아니다.
