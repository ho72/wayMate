# QA #12·#13·#14 수정과 회귀

2026-11-14 · PR #18의 QA 인계에서 우선 수정으로 지정한 세 항목을 순서대로 수정했다. v5 디자인을 선행 기준으로 사용한다. #15의 현재 대사 강조와 #17의 제출 기획서 통합은 이번 수정 범위가 아니다.

## #12 만남 종료와 연결 종료 정합성

A의 만남 취소, B의 만남 거절, B의 만남 취소는 현재 연결도 `ended`로 마무리한다. 연결 버전을 한 번 올리고 차량·모바일의 상대 projection과 대화 접근을 종료한다. 추가 잠금이 없는 상태에서는 기존 공개 철회 동작을 사용할 수 있다. 본인 여행과 이미 받은 handoff/ACK 기록은 보존한다.

확인되지 않은 전송 요청 자체의 취소와 실제 만남 취소는 구분한다. 서로 다른 제안의 요청 취소가 현재 만남을 종료하지 않게 하는 기존 테스트를 유지했다. 끝난 연결을 오래된 B 수락·중복 영수증·서버 재시작으로 되살리지 않는다.

내비 기록은 별도로 유지한다. pending/unknown 작업을 삭제하거나 취소만으로 경유지 제거 성공을 만들지 않는다. 늦은 실제/모의 추가 결과는 그대로 반영하고, 원래 목적지를 보존한 채 별도 운전자 제거 승인을 받는다. 새 회귀 7개가 세 종료 경로와 실제/모의 미확인→늦은 추가→별도 제거를 검사한다.

## #13 모의 내비 만남 취소 확인

모의 내비의 첫 취소 클릭도 실제 내비와 같은 확인창을 연다. 만남·연결 종료와 내비 정리가 별도임을 설명하고, `돌아가기`는 명령을 보내지 않는다. `만남 취소 확인`을 눌러야 현재 binding으로 한 번 전송한다.

제안 binding이 바뀌거나 사라지거나 내비 source가 전환되면 기존 확인창을 폐기한다. 처리 중 내비가 있어도 취소는 중단 동작으로 검토할 수 있으며, 기존 경유지와 결과 확인은 별도로 유지한다. 오프라인 production Compose 화면 테스트 5개로 pending/owned, 돌아가기, 한 번의 확인, 대상 변경/소멸, mock→real 전환과 real 확인 동작을 검증했다.

[오른쪽 3분할 앱 영역의 실제 확인창](evidence/qa12-14-2026-11-14/meeting-cancel-confirmation.png)은 841×1210이다. SDK·HTTP 없는 화면 fixture이며 실제 차량 경로 변경 증거로 취급하지 않는다.

## #14 관심사 부분 공개와 Q2

B의 필요한 공개 사실은 있지만 A의 공통 취향 근거가 없으면, 02번 `PEER_TOPIC_GENERAL` 대사를 사용한다.

> 같은 날 강릉을 여행한다는 이야기로 시작해보면 어때요? 오늘 어떤 여행을 하고 싶은지 직접 물어볼 수도 있어요.

A의 비공개 관심사는 공통 취향 주장이나 공개 동의로 바꾸지 않는다. B의 관련 필드가 비공개/누락이면 기존 모름 안내를 유지한다. 공통 취향이 모두 공개된 대표 Q2는 기존 대사를 유지한다. 새 함수·projection·재시작·비공개 보존·음원 회귀 7개를 추가하고 기존 UNKNOWN 고정 기대값을 개정했다.

중립 대사의 준비 합성 음원 1개를 추가했다. index와 audioCues의 자막/공개 필드 요구를 함께 갱신했으며 전체 준비 음원은 36개다. 음원 재생성 스크립트가 v5 캐릭터 메타데이터를 이전 절차형 이미지 설정으로 덮어쓰지 않도록 정리했다. Pleos에서 새 음원을 `prepared_sample`로 시작·완료하는 기기 검사도 통과했다. 플랫폼 TTS/STT 성공이나 실제 상대 음성으로 표시하지 않는다.
