# 순정 내비 공식 문서 재검토

이후 별도 AVD의 내부 메서드 호출 실험은 [22번](22_순정_내비_내부_스타일_변경_실험.md)에 기록한다. 호출은 반환됐지만 도로 표시까지는 성공하지 못했다.

2026-11-12. [20번](20_지도_스타일_분기_및_배포본_확인.md) 이후 공식 문서와 현재 환경을 다시 대조했다. **경로 탐색·경유지 제어는 기존 실제 검증에서 동작했지만 순정 내비의 도로 배경은 아직 표시되지 않는다. 추가 사용자 키나 필수 설정 누락을 이번 검토에서 찾지 못했다.**

## 확인 범위와 한계

설치·설정·프로젝트·NaviHelper·화면 정책·Virtual Console·FAQ·릴리즈 노트의 **가이드 25개 본문**을 읽었다. 내비 화면 요청 관련 **레퍼런스 24개는 제목만 있고 실질 본문이 비어 있었다.** `requestNavigationScreen`은 실제 브라우저에서도 같은 상태였다. 이 24개를 API 설명까지 확인한 것으로 계산하지 않는다. 사이트 전체의 모든 문서를 읽었다는 뜻도 아니다.

공식 사이트 검색에서 `지도`는 지도 앱 개발·카테고리·심사 안내를 반환했고 `coral`은 결과가 없었다. 검색 무결과만으로 지원 불가를 판정하지 않는다. URL·본문 유무·추출 텍스트 해시는 [검토 목록](evidence/native-map-official-docs-recheck-2026-11-12.json)에 기록했다. 웹 본문 전체는 커밋하지 않는다.

## 공식 안내와 현재 상태 대조

| 항목 | 공식 안내 | 현재 판단 |
|---|---|---|
| Mac 설치 | Mac용 ARM 피드, Pleos 2.1.0/API34, RAM 4GB, cold boot | 기존 설치·비교 시험 조건과 대조. Mac이라는 이유만으로 설치 대상을 잘못 선택한 것은 아님 |
| GPU | NVIDIA/AMD 요구사항 표 | Apple M3 순정 지도의 지원·미지원이나 필수 백엔드는 명시적으로 확인 못함 |
| 프로젝트·키 | NaviHelper/Vehicle State 신청 불필요. 2.1.0 이후 CRN 불필요. 프로젝트 ID는 심사, Client ID/Secret은 서버 연결형 SDK용 | 사용자가 두 SDK 모두 사용 가능으로 확인. 지도 진단용 추가 키 요청 근거 없음 |
| SDK 역할 | 순정 Navi Service에 경로·경유지·정보·화면 요청 전달 | 경로 제어 성공과 순정 배경 렌더링 성공을 구분 |
| 권한 | NAVI_ROUTE는 정보/Trip, NAVI_ROUTE_SEARCH는 경로/경유지, NAVI_CUSTOM_MAP은 requestNavigationScreen | 사용 중인 경로 권한 선언됨. CUSTOM_MAP 추가로 도로를 켠다는 안내는 없음 |
| 지도 앱 분류 | Maps/Navigation 앱 카테고리·포커스 규칙 | 동행 앱 wayMate의 APP_MAPS 전환을 배경 복구책으로 적용하지 않음 |
| 화면·폼 팩터 | 분할 창 배치, Host Display Bridge 가상 디스플레이 시험 | 도로 데이터 활성화·다운로드 절차가 아님 |
| Virtual Console | 차량 상태·이벤트 시뮬레이션 | 읽은 사용 가이드에 도로 스타일 활성화 항목 없음 |
| CCS·지역 FAQ | CCS 연결 명령은 실차 전용이며 에뮬레이터 사용 금지. 지역 property는 환경 정보 설명 | CCS 연결·지역 property 변경을 지도 복구책으로 실행하지 않음 |
| 공개 릴리즈 | Emulator 2.1.0, NaviHelper 3.0.5 | 좌표 인자 순서 변경은 기존 수정과 일치. 도로 배경 수정·coral 제한 설명은 확인 못함 |

`NAVI_CUSTOM_MAP`이라는 이름만으로 지도 스타일 변경 기능이 있다고 해석하지 않는다. 본문이 비어 있는 화면 API는 로컬 공식 SDK 3.0.5 AAR 공개 선언과 navi-data 3.0.4 모델로 보완 확인했다. `requestNavigationScreen(NavigationScreenRequest)`는 기존 순정 화면 요청이며, 확인한 공개 API에서 임의 스타일 설정 메서드는 찾지 못했다. 실제 화면 요청 호출 시험이나 지도 내장 구현을 새로 완료했다는 의미는 아니다.

## 왜 배경이 안 나오는가

현재 가장 구체적인 단서는 [20번의 factory APK 분석과 런타임 로그](20_지도_스타일_분기_및_배포본_확인.md#구체적으로-확인한-스타일-선택)다. `coral` 환경은 `connect_empty` 스타일을 직접 선택하고, 확인한 공개 스타일에는 도로 레이어가 없다. 경로 계산 서비스가 응답해도 배경에 도로가 나타나지 않는 현상과 부합한다.

이는 **공식 문서가 발표한 지원 제한이 아니라 배포 파일·실행 로그에서 관측한 동작**이다. 별도 지도 합성 경로와 GPU/GPS 영향까지 모두 배제하지 못했다. 따라서 ‘Mac은 지도 미지원’, ‘coral은 의도적으로 빈 지도만 제공’, ‘GPU만 바꾸면 해결’이라고 확정하지 않는다.

검토한 공개 문서에는 이 분기의 의도, 개발자가 전환할 공식 환경·스타일 설정, 해당 현상을 고친 배포 버전이 설명되어 있지 않았다. 20번의 공개 ARM 피드 revision 2와 자산 목록 확인에서도 더 새 공개 수정본을 찾지 못했다. 비공개 배포본의 존재 여부나 복구 불가능을 결론 내리는 근거는 아니다.

**사용자 Playground 설정 누락으로 설명할 근거는 없고, 현재 순정 앱/배포 환경의 빈 스타일 선택이 가장 구체적으로 확인된 문제 지점이다. 의도된 제한인지 배포본 오류인지는 미확정이며 도로 배경 복구도 미완료다.** 이번 작업은 문서 재검토이며 AVD·APK·권한·서버 데이터·실제 내비 기록은 변경하지 않았다. 외부 문의와 메일도 진행하지 않는다.

## 후속: connect_empty를 바꾸는 공식 설정 확인

같은 날 공식 GitHub 샘플 코드·기존 순정 설정 캡처·factory Manifest·SDK 선언까지 범위를 넓혔다. **확인한 범위에서 개발자에게 공개된 스타일 URL/환경 전환 절차는 찾지 못했다.** 내부 구현에 전환 기능이 전혀 없다는 뜻은 아니다. [후속 근거 목록](evidence/native-map-style-setting-followup-2026-11-12.json)에 출처와 확인 한계를 기록했다.

| 경로 | 추가 확인 결과 |
|---|---|
| 공식 NaviHelper 샘플 | README, SdkApi.kt, NaviHelperViewModel.kt, NaviTestData.kt 본문 확인. 경로·경유지·화면 요청 예제이며 스타일 URL이나 서버 환경 변경 예제는 없음 |
| requestNavigationScreen | 샘플은 RouteOptionList를 요청. 경로 옵션 화면 요청을 도로 스타일 선택으로 해석하지 않음 |
| SDK의 InternalApi | 로컬 공식 AAR의 선언은 updateOccupiedRegion(Rect)만 제공. 지도 스타일 변경 메서드는 발견 못함 |
| 순정 일반 설정 | 보존된 캡처/XML에는 경로·충전소·사운드·버전 항목이 있으며 스타일 URL/환경 선택은 발견 못함. 이번에 기기를 다시 조작한 것은 아님 |
| 순정 내부 setMapStyle | factory 코드에 메서드는 있으나 wayMate가 호출할 공개 SDK나 공식 설정이라는 근거 없음. 내부 메서드 존재와 외부 지원은 구분 |
| 외부 실행 경로 | 기존 factory Manifest에서 명시적인 스타일/환경 변경 exported 항목을 발견 못함. 모든 런타임 handler 부재까지 증명한 것은 아님 |

공식 조직의 [NaviHelper 샘플](https://github.com/Pleos-Playground/pleos-sample-navi-app)은 기본 내비 앱에 NaviService로 요청한다고 설명한다. [API 목록](https://github.com/Pleos-Playground/pleos-sample-navi-app/blob/main/app/src/main/java/ai/pleos/playground/navidevapp/data/model/SdkApi.kt)과 [호출 구현](https://github.com/Pleos-Playground/pleos-sample-navi-app/blob/main/app/src/main/java/ai/pleos/playground/navidevapp/screen/vm/NaviHelperViewModel.kt)에 스타일 전환 예제는 없다. [테스트 데이터](https://github.com/Pleos-Playground/pleos-sample-navi-app/blob/main/app/src/main/java/ai/pleos/playground/navidevapp/data/sample/NaviTestData.kt)의 화면 요청도 경로 옵션 목록이다.

새로 확인한 [공식 게시판 #34](https://github.com/Pleos-Playground/pleos-playground-api/discussions/34)에는 2026-11-08 동일 배경 누락 질문과 11-12 Windows 11/NVIDIA 환경의 동일 증상 댓글이 있다. **다른 개발자의 보고이며 제공사 답변은 없었다.** Mac만의 문제라는 가설을 약화하는 참고 자료로만 취급하고, GPU 원인 배제나 공식 미지원 선언으로 사용하지 않는다. 댓글의 missing token 문구도 추가 사용자 지도 키가 필요하다는 증거로 간주하지 않는다.

[공식 FAQ #24](https://github.com/Pleos-Playground/pleos-playground-api/discussions/24)는 2025-11-24 기준 기본 지도 앱 우선순위가 시스템에 의해 선택된다고 설명한다. 이것은 앱 선택에 관한 안내이며 connect_empty를 바꾸는 스타일 설정이 아니다. [현재 위치 질문 #32](https://github.com/Pleos-Playground/pleos-playground-api/discussions/32)는 FAQ 분류에 있지만 개발자 질문·답변 0개이므로 공식 해결책으로 인용하지 않는다.

공식 GitHub 코드 검색의 connect_empty/MapStyle 결과는 0개였지만 검색의 완전성을 보장하지 않는다. 추가로 발견한 플랫폼 ProvisioningManager.getEnvironment 레퍼런스는 웹 도구에서 읽지 못했으므로 환경 변경 가능·불가능의 근거로 사용하지 않았다.

**현재 적용 가능한 공식 전환 설정은 확보하지 못했다.** 순정 앱 내부의 다른 환경/스타일이 존재한다는 이유만으로 임의 URL 교체나 서버 전환을 적용하지 않았다. 에뮬레이터·앱·서버 상태는 그대로이며 외부 문의, 메일, 게시판 글/댓글도 작성하지 않았다. 배경 지도 복구는 미완료다.

## 2026-11-15 현재 재확인

사용자의 ‘에뮬레이터에서 지도가 원래 표시되지 않는가’ 질문에 따라 기존 진단을 재검토하고 공개 문서/배포 피드/현재 기기를 읽기 전용으로 확인했다. **공식 미지원/정상 제한으로 확정할 근거는 여전히 없으며, 순정 내비 배경 표시 문제는 미해결이다.**

- 현재 emulator-5554의 순정 내비 버전은3.3.2-rc5-hotfix.3이며, 두루밋 창이 없는 순정 내비 화면에서도 현재 위치/수정구 시흥동 표시만 있고 도로 배경은 비어 있었다. 오늘은 앱/내비 재시작·AVD 설정 변경·경로 변경을 하지 않았다.
- 공식 게시판 [#34](https://github.com/Pleos-Playground/pleos-playground-api/discussions/34)는 여전히Unanswered, 댓글1개다. Windows11/NVIDIA에서도 같은 현상을 보고했으며 제공사 답변은 없다. 이는 개발자의 직접 관찰 보고이며 공식 원인/지원 판정은 아니다.
- [현재 공식 릴리즈 노트](https://document.pleos.ai/docs/pleos-only/release-note/emulator-release-note)는2.1.0/2026-10-19다.
