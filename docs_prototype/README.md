개발을 나눌 때는 06번의 책임·파일 경계를 보고 05번과 실제 작업 이슈에 이름·가용 시간을 기록합니다. 전체 팀은 5명으로 확인됐고, 개발 인원·역량·기획서 제출 형식·기한은 아직 미정입니다.

화면을 눈으로 검토할 때는 08번의 [전체 PDF](wireframes/v1/waymate-screen-spec-v0.4.pdf)를 봅니다. 피드백은 `WF-019 / 요소 4 / 변경안`처럼 남깁니다. 기존 기본 범위 B와 이번 요청의 개인 장소·일정 연동 확장 E, 기존 추가 O를 구분했으며 E는 구현 전 계약 갱신이 필요합니다. 목표 화면과 현재 구현 상태는 각각 08번과 10번으로 구분합니다. 07번은 v2 역사 기록입니다.

## 추가 요구사항 · Pleos 여행 계획 지속 표시

설정·저장한 여행 계획을 Pleos 기본 홈에서 계속 확인할 수 있어야 합니다. 01번의 서비스·제작 요구, 02번 S05 시연, 03번 5.3절의 표시·복원 기준, 08번 WF-012와 05번 Q29에 반영했습니다. Q29는 미실시입니다. 표시 요구는 최신 SVG/PDF에도 반영했으며 10~12번 실제 구현 증빙은 보존합니다.

## 정리 v2 · 문서 반영 기준

- 매칭은 탑승 전 모바일에서 진행하고 Pleos에서는 새 매칭을 하지 않습니다.
- 저장한 여행 계획을 Pleos 기본 홈에서 지속 표시합니다.
- 최종 선택은 A·B에게 같은 단계에서 열고 상대 선택을 보지 않은 채 독립 제출합니다. 양쪽 제출 후 모두 함께이면 동행, 하나 이상 각자이면 본인 여행으로 이어갑니다.

동시 선택을 01~05·08·09와 화면 원본·최신 SVG/PDF·뷰어에 반영했습니다. 구현·검수는 미완료이며 DOCS 공유·목차 분담은 팀이 별도로 진행합니다. 아래 과거 개정 이력의 순차 선택 규칙은 이 기준으로 대체합니다. v0.1~v0.3 PDF는 과거 산출물입니다.

## 작성 기준

- 프로젝트 개발 가제는 `wayMate`로 통일합니다. 최종 서비스명은 별도로 결정합니다.
- 기능 ID `DM01`~`DM11`은 후속 문서에서도 동일하게 사용합니다.
- 서비스 목표, 목업의 실제 동작, 대본·시연 데이터에 의한 재현을 구분합니다.
- 후속 문서에서 제작 범위를 바꾸면 01번 문서와 관련 검수 항목도 함께 갱신합니다.
- 작성 예정 문서는 실제 파일이 생긴 뒤 링크를 추가합니다.

**추천·대화 연결은 탑승 전 모바일, 연결 이후 이동 경험은 Pleos**가 기준입니다. 01~05는 v0.8, 06·08은 v0.4, 09는 v0.2입니다. 기존 53개 WF 번호를 유지했으며 PDF는 59쪽입니다. 아래 v0.7은 이전 개정 이력입니다.

| Pleos P01~P04 | 여행/연결 수신 → 큰 내 친구 홈·상대 캐릭터·콘텐츠 → 만남·순정 내비 → 두 결말·본인 여정 |

## v0.7 Pleos 중심 여정 반영 · 이전 이력

당시 개정은 01~05 v0.7·06~08 v0.3이며, 모바일 준비 후 차량 추천/매칭으로 옮긴 안이었습니다. 이 역할 배치는 v0.8에서 모바일 매칭으로 대체했습니다. 화면 53개·PDF 59쪽이며 기존 WF 번호를 유지했습니다. 설계 갱신 당시 담당자·마감은 미정, 검수·주행/SDK 검증은 미실시였습니다. 이후 부분 구현·실제 SDK 관측은 10번에 기록합니다.

기획 보충: [01번 5.4절](01_목업_기획_범위_정의서.md#54-차-밖에서-모바일로-다음-여정-준비--후속-기획)에 식사·관광 중 모바일로 다음 장소 후보를 준비하고 재탑승 후 Pleos에서 확인·안내하는 방향을 추가했습니다. 차 밖에서 선택적으로 사용하는 후속 경험이며, 이번 시연·화면·API·작업/검수·PDF 범위와 차량 내 모바일 재조작 없이 완주하는 기준은 유지합니다.

|---|---|
