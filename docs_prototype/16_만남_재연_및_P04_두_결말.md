# 만남 재연과 P04 두 결말

2026-11-12. 02번 S09~S12, 03번 §5.9~5.10·O01, 04번 최종 선택/재시연 계약과 Q07·Q08·Q13을 기준으로 구현했다. 모바일의 최종 매칭 확인과 만남 뒤 P04 선택은 별도 동의다. `docs_proposal`은 변경하지 않는다.

## 진행과 시연 방법

1. 모바일 매칭·차량 수신 → 양쪽 만남 동의 → 차량의 별도 내비 승인과 실제 경유지 반영 확인을 마친다.
2. O01에서 **만남 시작으로 이동**을 누르면 P03의 14:15 가상 만남 재연을 연다. 활성·정차 차량, 최신 이중 경로 관측, 같은 만남의 승인/반영 기록이 필요하다. 도착을 GPS로 감지하지 않는다.
3. **만남 종료**로 14:35의 P04를 연다. A 차량과 B 시연 패널에 두 선택이 동시에 열린다. A는 선택 → 제출 → 별도 확인으로 제출한다. B는 O01에서 본인 선택을 지정한다.
4. 첫 응답만으로는 어떤 값이든 pending이다. 양쪽 together일 때만 함께 산책하며, 나머지 세 조합은 각자의 여행과 내 친구 대화·휴식/사진·다음 일정으로 이어진다. 제출 전 수정 가능, 제출 후 변경 불가다.
5. 확정된 두 결말에서 O01의 **최종 선택 재시연**을 누르면 새 finalId·증가한 round·새 공통 requestId로 양쪽 미선택부터 다시 연다. 전체 초기화는 별도다.

만남은 일반 인사와 공개 근거가 충분한 친숙한 인사로 나뉜다. 후자는 현재 연결에서 차량이 Q1 공개 답변을 실제 표시한 cue, B 공개 프로필, A가 명시적으로 공개한 바다 산책/카페 관심사, 이야기의 peerIntroSeen이 모두 필요하다. 누락되면 일반 인사다. peerIntroSeen은 O01에서 재연 전에만 조정하는 이야기 설정이며 실제 B 열람 증거가 아니다.

차량은 만남/산책 대사를 재연 자막으로 표시하고 내 일정 조회·내 친구로 돌아가기를 제공한다. 각자 결말은 A가 함께를 원했더라도 혼자 있고 싶었다고 단정하지 않는다. 조기 종료와 선택 중 연결 중단은 완료 만남의 정상 결말과 다른 안내를 쓴다. 이유 입력·후기·장식은 이번 범위에 추가하지 않았다.

## 독립 선택과 복원 경계

서버는 내부 A/B 슬롯을 한 저장 단위로 갱신하고 두 슬롯이 모일 때만 결과를 확정한다. 차량 DTO에는 A 본인 선택, O01에는 B 본인 선택만 제공하며 모바일에는 둘 다 제공하지 않는다. 상대 제출 여부 표식이나 원시 슬롯·checkpoint·이력은 노출하지 않는다. 조회·오류·영수증도 현재 조회 역할의 projection을 사용한다. 함께 결과 자체로 알 수 있는 합의 외에 상대 선택/이유를 표시하지 않는다. 이는 로컬 시연 역할 분리이며 운영용 인증 시스템은 아니다.

중복 명령은 기존 영수증을 재사용한다. 과거 finalId/round/requestId는 거부하고, 거의 동시 제출의 버전 충돌은 최신 본인 상태를 확인한 뒤 사용자 확인을 거쳐 다시 제출한다. 시간 경과로 미제출 값을 만들지 않는다. 차량은 확인 창에서 검토한 대상과 현재 binding까지 대조해 이전 선택의 확인을 새 회차에 사용하지 않는다. 정상 모드에서 선택 중 연결 종료는 cancelled이며 미제출 슬롯을 각자로 채우지 않는다.

재시연은 완료 만남의 표시 맥락만 유지한다. 닫힌 live 연결·철회한 공개를 복원하지 않고 현재 내비/제한/복구를 과거 값으로 덮어쓰지 않는다. 새 메시지·만남·SDK 추가는 UI와 서버에서 차단한다. 현재 SDK 사실 보고·중단·필요한 제거·안전한 전체 초기화는 허용한다. 정상 소유 경유지가 존재하는 것만으로 재시연을 잠그지는 않는다.

기존 v4 저장소에는 선택적 journey 필드를 더해 읽기 호환을 유지했다. v2/v3 계약·예제는 변경하지 않았다. `server/v4/ending.mjs`, `shared/config/ending-v4.mjs`, 차량 `EndingScreen`/`FinalSubmissionPolicy`, O01이 각 책임을 담당한다. 생성 예제의 SDK 보고는 계약 시험용 모사 데이터이며 실제 SDK 증거와 구분한다.
