# QA 시연 검증 결과와 수정 인계

2026-11-14 · 기준 커밋 `901a3250b6e3b3a367c59b3bcf5ace753a2930f9`

모바일 브라우저에서 대본대로 준비·공개·매칭·전달을 마치고 탭을 닫은 뒤, 실제 Pleos 에뮬레이터의 production 차량 앱으로 두 결말까지 진행했다. 대표 흐름은 완주했다. 다만 만남 취소·거절 상태, 모의 내비 취소 확인, 부분 공개 대사와 일부 화면 피드백에 보완할 부분이 있다. 제출 기획안은 현 시연보다 넓은 기능을 MVP로 약속하고 있어 범위 정리가 필요하다.

실행 환경은 macOS ARM64, Node 22.22.2, JDK 21.0.12, Android SDK 35, Pleos Connect 2.1.0/API34, `com.waymate.app.mock`이다. 실제 내비 SDK를 호출하는 real 앱은 빌드만 확인했다. 현재 구현 기준은 `docs_prototype` 01~05 및 최신 23·24·26번이다. 제출 초안 `docs_proposal`과 [Google Docs 원본](https://docs.google.com/document/d/1yB8ing7vMZh4XTfFKSRv5gdV2VTd1iq5htS-nUwDkY0/edit?tab=t.0), [개발계획 담당 탭](https://docs.google.com/document/d/1yB8ing7vMZh4XTfFKSRv5gdV2VTd1iq5htS-nUwDkY0/edit?tab=t.nt4reg4euou3)을 별도로 대조했다. 문서는 검토 시점 이후 수정될 수 있다.


## 개발 담당자가 먼저 볼 내용

이 문서가 이번 QA 인계의 진입점이다. 담당 이슈의 재현 순서와 완료 조건을 확인하고 APP-01 → APP-02 → APP-03을 우선 수정한다. APP-04·05는 촬영 조작·시각 정합성 개선이다. 기획서 불일치는 문서 작업 이슈에서 현재 완료·시연 재현·후속 목표를 합의한다.

1. [개발 현황](../docs_개발/README.md)에서 기본 시연과 선택 확장 범위를 확인한다.
2. 기대 대사·분기는 [02 시연 시나리오](02_시연_시나리오_및_대본.md), 화면·취소 확인은 [03 화면 설계](03_화면_및_상호작용_설계서.md), 상태·동의·API는 [04 개발·연동 명세](04_개발_및_연동_명세서.md)를 따른다.
3. 수정 책임은 [06 분담 가이드](06_개발_아키텍처_및_분담_가이드.md), 재검수 동선은 [24 시연 운영표](24_main_통합_확인_및_시연_운영표.md), 주행 제한은 [26 주행·정차 모드](26_캐릭터_중심_주행_정차_모드.md)를 확인한다.
4. 모바일 온보딩을 바꿀 때는 [27 실제 AI 상담](27_실제_AI_상담_및_소개_초안.md)도 확인해 기존 대본 모드와 선택적 AI 모드를 함께 보존한다.

수정 PR에는 해당 버그 이슈를 연결하고 검증 커밋·재현 경로·실제 확인 결과를 남긴다. QA 담당자가 수정 커밋에서 완료 조건과 인접 분기를 다시 검사한 뒤 머지한다. 이 보고서를 추가하는 문서 PR은 버그 수정 완료를 의미하지 않는다.

## 검증 기준과 게시 기준

실행 검증 대상은 `901a325`의 기본 3000번 대본 시연·mock 앱이다. 이 문서 PR은 이후 `b84ebec`에서 시작했다. 그 사이 PR #10·#11로 개발 현황 문서와 선택적 실제 AI 상담이 추가됐다. APP-01~04의 원인 파일과 APP-05의 고정 대표 이미지가 최신 main에도 유지되는 것을 정적 비교로 확인했다. 추가로 최신 main의 격리 coordinator 네 경로와 Q2 함수를 재실행해 APP-01·03이 동일하게 재현됨을 확인했다. 이는 제한된 원인 재현이며 최신 main 전체 273/46/18개 검사나 새 AI 확장 재검증을 의미하지 않는다. [게시 시점 원인 확인](evidence/qa-2026-11-14/latest-main-check.json)을 함께 참조한다.

차량 A의 조작은 실제 production Compose UI에서 실행했다. S05 이후 B 응답·모의 내비 결과·시간 전환·결말 재시연은 O01 역할의 정상 HTTP API로 시뮬레이션했다. 모바일 연결의 B 수락은 O01 브라우저 버튼으로 수행했다. 실제 B 사용자·실시간 통신을 검사한 결과가 아니다. 첫 네이티브 고정 시나리오는 확장 창에서 39.13초에 통과했다.

촬영 목표인 오른쪽 3분할 창에서도 같은 production 전체 흐름을 다시 실행해 43.627초에 통과했다. 이 반복 검사의 모바일 준비는 정상 web-role API로 대표 소개·공개 항목 8개를 설정했으며, 최초 실제 브라우저 검사를 다시 수행한 것으로 집계하지 않았다. 모든 차량 단계 캡처에서 841×1210dp·x=1718·y=90·fontScale=1을 확인했고 Activity 재생성 이후에도 같은 위치와 크기를 검사했다. 이 두 자동화 실행 시간은 발표 리허설 실측값이 아니다.

신규 기기 통합 검사는 전체 흐름 두 창 모드와 안전 초기화가 통과했고, 취소 정합성 검사는 실제 결함을 검출해 실패했다. 기존 기기 회귀는 18개 모두 통과했다. 130% 글자 검사는 실제 창에 표시한 오프라인 검수 Activity이며 서버 여정을 완주한 검사와 구분한다.

3분할 창의 안전 초기화도 7.289초에 통과했다. 검수 종료 후 정상 제거·동일 차량 ACK로 회차 5를 열었고, 여행·전달·차량 활성화·진행 중 초기화는 모두 비어 있으며 모의 경유지는 0개다. 검수 종료 시 서버·모바일·시연자 및 일반 차량 앱의 초기 상태를 확인했다. 일반 차량 앱의 최종 재실행 창은 기본 확장 크기이며, 촬영 목표 3분할의 전체 여정 통과 증거와 구분한다.

## 앱 동작·화면에서 발견한 문제

**APP-01 · 우선 수정 · 만남 취소·B 거절 뒤에도 상대 연결이 남는다.** 모바일 연결 → 차량 만남 제안 후 A 취소, B 거절 또는 B 취소를 실행하면 `meeting=cancelled/declined`, `journey=early_end`이지만 `connection=linked`, 상대는 솔바람으로 남는다. 공개 철회 동작도 제공되지 않는다. 반면 제안 전 A의 ‘이번에는 만나지 않기’는 정상적으로 연결을 끝낸다. A 취소는 실제 차량 UI에서도 재현해 홈의 ‘솔바람 · 연결됨’을 확인했고 B 거절·취소는 coordinator 격리 검사로 확인했다. 대본은 거절·취소 시 약속과 상대 연결을 함께 마무리하도록 요구한다. 취소 처리에서 연결 종료·상대 projection 정리·공개 철회 가능 조건을 함께 맞춰야 한다. **APP-02 · 우선 수정 · 모의 내비 화면의 ‘만남 취소’에 확인창이 없다.** 만남 합의 → 모의 내비 화면에서 취소를 누르면 콜백을 즉시 호출한다. 실제 차량에서도 한 번의 클릭 직후 meeting=cancelled로 바뀌는 것을 확인했다. 실제 내비 화면과 만남 화면은 확인창을 사용한다. 무엇이 끝나고 경유지 정리는 별도로 필요하다는 설명을 보여준 뒤 최종 확인을 받아야 한다. **APP-03 · 부분 공개 정합성 · S06 Q2의 중립 대체 대사가 빠져 있다.** A가 관심사를 공개하지 않고 연결한 상태에서 ‘처음 만나면 무슨 얘기를 하면 좋을까?’를 고르면, B의 공개 근거가 있어도 “아는 소개에 없다”는 답이 나온다. 대본은 공통 취향의 근거만 없을 때 같은 날 강릉 여행 이야기로 시작하는 중립 대사를 요구한다. B 정보 자체가 없는 경우와 A가 관심사를 비공개로 둔 경우를 구분해야 한다. 기존 테스트도 UNKNOWN을 기대하므로 테스트가 함께 바뀌어야 한다. ## 기획서와 구현의 정합성

**SPEC-01 · 제출 전 정리 · 주행 음성 기능의 약속이 구현보다 넓다.** 개발계획 담당 탭은 STT로 만남 동의·경로 승인·최종 선택을 받는 것을 MVP에 넣고 있다. 현재 구현은 해당 업무를 정차 상태에서 처리하며, 주행은 정적 캐릭터·짧은 준비 음원·중단만 제공한다. 원본 3.3.2의 주행 중 ‘전화 연결’도 새 통화 시작과 유지·후속 목표를 구분해야 한다. STT·실시간 문답을 후속으로 옮기거나 새 개발·검수 범위를 합의해야 한다. [현재 주행 기준](https://github.com/ho72/wayMate/blob/901a3250b6e3b3a367c59b3bcf5ace753a2930f9/docs_prototype/26_%EC%BA%90%EB%A6%AD%ED%84%B0_%EC%A4%91%EC%8B%AC_%EC%A3%BC%ED%96%89_%EC%A0%95%EC%B0%A8_%EB%AA%A8%EB%93%9C.md#L9), [담당안 검토 원문](https://docs.google.com/document/d/1yB8ing7vMZh4XTfFKSRv5gdV2VTd1iq5htS-nUwDkY0/edit?tab=t.nt4reg4euou3)

**SPEC-02 · 제출 전 정리 · 위치 기반 추천·GPS 도착이 현재 시연과 다르다.** 담당안은 현재 위치로 장소·시간을 다시 계산하고 GPS 도착을 감지하며 FusedLocation/Vehicle 데이터를 쓰는 것을 MVP로 적는다. 현재는 고정 바다쉼표 카페·고정 시간과 O01의 만남 시작·종료 재연이다. 영상·완료 설명에는 준비 데이터와 시연자 전환을 명시하고 동적 계산·자동 도착은 후속 범위로 구분해야 한다. [고정 만남 데이터](https://github.com/ho72/wayMate/blob/901a3250b6e3b3a367c59b3bcf5ace753a2930f9/mock-app/server/v4/social.mjs#L42), [담당안 검토 원문](https://docs.google.com/document/d/1yB8ing7vMZh4XTfFKSRv5gdV2VTd1iq5htS-nUwDkY0/edit?tab=t.nt4reg4euou3)

**SPEC-03 · 제출 전 정리 · 새 목적지·추가 경로·만족도조사가 기본 범위에 섞여 있다.** 담당안에는 다음 목적지 설정, 함께 결말에서 새 장소·경로, 만족도조사가 포함돼 있다. 현재 시연은 기존 목적지를 유지하고 승인한 고정 경유지 추가·제거와 두 결말을 제공한다. 함께 결말도 14:35~14:55 산책과 기존 다음 일정 유지이며 새 경로를 자동 추가하지 않는다. 후기·설문은 기본 시연에서 미채택이다. [현재 두 결말 기준](https://github.com/ho72/wayMate/blob/901a3250b6e3b3a367c59b3bcf5ace753a2930f9/docs_prototype/02_%EC%8B%9C%EC%97%B0_%EC%8B%9C%EB%82%98%EB%A6%AC%EC%98%A4_%EB%B0%8F_%EB%8C%80%EB%B3%B8.md#L405), [담당안 검토 원문](https://docs.google.com/document/d/1yB8ing7vMZh4XTfFKSRv5gdV2VTd1iq5htS-nUwDkY0/edit?tab=t.nt4reg4euou3)

**SPEC-04 · 제출 전 정리 · Google Docs ‘기획서 원본’의 5·6번은 아직 공란이다.** 별도 담당 탭의 글이 제출 본문으로 통합되지 않았다. 범위 충돌을 정리한 뒤 개발 계획·기대효과를 원본에 통합하고 최종 제출 탭을 확정해야 한다. [검토 시 원본](https://docs.google.com/document/d/1yB8ing7vMZh4XTfFKSRv5gdV2VTd1iq5htS-nUwDkY0/edit?tab=t.0)

## 판정의 한계와 촬영 준비

이번 성공은 모의 내비를 사용한 앱 기능 흐름의 검증이다. 실제 내비 경유지 반영·실차 주행·실제 상대 통신·STT·사용자 가설 검증을 통과한 것으로 합산하지 않는다. 이후 추가된 선택적 실제 AI 상담의 실행 결과도 이 보고서에 합산하지 않으며 27번의 별도 기록을 따른다. 순정 내비 도로 배경은 기존 보류 항목이며 이번 신규 결함으로 집계하지 않았다. 준비 음원의 재생·중단은 기기 상태로 검사했고 발음·음질의 사람 청취 평가와 발표 7~8분 실측은 별도다.

기본 대본 모드에서 음식 후속 질문은 ‘맛집 탐방을 좋아해’라는 정확한 준비 문구에서만 열린다. 의미가 비슷한 문장에 내용을 덧붙이면 기본 질문 순서로 진행한다. 이는 `web/README.md`에 명시된 준비 분기의 한계라 기능 오류에 포함하지 않았으며 촬영 대본의 입력 조건으로 기록한다. 기본 공개가 별명·캐릭터만인 것도 동의 설계다. 대표 대본 Q2와 친숙한 만남 대사를 촬영하려면 소개값 선택에 더해 관심사 등의 공개 항목도 별도로 승인해야 한다.

촬영 전에는 APP-01·02를 먼저 수정하고 같은 취소·거절 분기를 재검수하는 것을 권한다. 이후 APP-03의 부분 공개 대사를 맞추고 APP-04의 현재 대사 표시를 보완하면 촬영 조작이 수월해진다. 제출 기획안은 현재 완료·대본 재현·후속 개발 범위를 하나의 기준으로 통합할 필요가 있다.
