# 모바일·시연자 웹 · WEB 담당

`index.html`·`style.css`·`app.js`는 본인 여행 준비의 첫 연결 화면입니다. 저장 UI와 실제 HTTP·영수증 복구는 구현했고, M01 대화 연출·M02~M04의 전체 흐름과 O01은 구현 전입니다. [07 실행 안내](../../docs/07_첫_전달_실행_및_계약.md)와 [03 전체 화면](../../docs/03_화면_및_상호작용_설계서.md)을 구분해서 확인하세요.

- `app.js`: 명세의 질문 선택·프로필·비공개·고정 여행 저장을 순서대로 실행합니다. 각 단계 영수증 후에만 다음 단계로 갑니다. 중간 실패 시 일부 저장 상태가 남을 수 있으며, 최종 여행 저장 성공으로 표시하지 않습니다.
- `shared/client.mjs`: 안정된 클라이언트 ID, 500ms 단일 poll, 명령 봉투, 타임아웃 시 pending 보존·영수증 조회·사용자 재전송을 담당합니다. 회차·버전은 서버 응답을 기준으로 읽습니다.
- `views/`: 향후 화면별 구현 위치. `operator/`는 O01 예약 경로입니다.

서버에서 받은 `handoff.acknowledged`만 차량 수신 확인으로 표시합니다. 저장 버튼 클릭·GET handoff·로컬 상태만으로 완료 처리하지 않습니다. 비공개 본인 여행만 지원하고 상대 정보·공개 승인 화면은 만들지 않습니다.

조회는 화면이 보일 때만 진행하고 요청 중 중복 poll을 만들지 않습니다. localStorage에는 클라이언트 ID와 미확인 명령만 저장하며 서버 업무 상태를 대체하지 않습니다. 브라우저를 새로 열어 pending 영수증이 없으면 요청을 유지하고 **같은 요청 다시 전송**을 제공합니다.
