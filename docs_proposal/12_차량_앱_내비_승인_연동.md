# 차량 앱의 실제 내비 경유지 승인

> 최신 목표(v0.8)는 **탑승 전 모바일 추천·매칭 → Pleos 이동 경험**이며 [04 개발 명세](04_개발_및_연동_명세서.md)의 schemaVersion 4를 따른다. 이 문서의 당시 실행/검증 기록·v2/v3 계약은 보존한다. 이전 P06/P07 차량 매칭 방향을 새 목표로 적용하거나 이 기록을 모바일 매칭 완료 증빙으로 사용하지 않는다.

이 문서는 04의 전체 만남 흐름과 구분되는 `driver_waypoint` 구현 계약이다. 운전자가 본인 여행에 검증된 시연 장소인 소프트웨어드림센터를 추가하거나, wayMate가 추가한 그 경유지를 제거한다. 상대 매칭·만남 동의·장소 검색·일정 ETA·음성은 이 구현에 포함하지 않는다. 현재 순정 내비 목적지를 읽어서 유지하며, 앱에서 `requestRoute`나 `cancelRoute`를 호출하지 않는다.

차량 홈의 **내비 경유지 → 경유지 추가 승인 → 승인하고 추가**가 진입 경로다. 제거는 **wayMate 경유지 제거 승인 → 승인하고 제거**를 사용한다. 정차 여부가 미확인이거나 제한이 있으면 승인할 수 없다. 실제 SDK는 `real` 빌드에만 존재하고 `mock`은 변경을 차단한다.

## JSON과 실행 순서

기존 schemaVersion 3에 내비 명령·선택적 `navigation` 상태를 추가한다. 기존 v3 파일을 읽을 수 있고, v2 계약과 예제는 변경하지 않는다. 위치·실행 기록은 차량 projection에만 포함한다. 웹에는 `navigation: null`을 반환한다. 로컬 시연 서버의 역할 헤더는 운영 인증이 아니다.

1. `CAR_SESSION_OPEN.navigationSource`는 real/unsupported다. `CAR_STATUS.uiContext`는 handoff/home/navigation이다.
2. `NAV_OBSERVE`는 SDK의 연속 두 관측과 독립 POI 조회를 보고한다. 관측은 같은 SDK 세션이며 첫 조회 완료부터 두 번째 조회 시작까지 1초 이상 떨어져야 한다. 서버는 수신 후 2초, 앱은 마지막 SDK 완료 후 2초 안의 관측만 실행에 쓴다.
3. 운전자가 검토한 경로와 승인 후 새로 읽은 경로가 같아야 `NAV_APPROVE`를 보낸다. 서버는 활성 여정·현재 차량/epoch·정차·화면 활성·navigation 화면·현재 경로·미확인 실행·소유권을 확인하고 시도 ID를 저장한다.
4. 앱은 AtomicFile에 `awaiting_grant` 실행 기록을 동기 저장한 뒤 `NAV_DISPATCH_BEGIN`을 보낸다. 서버는 `may_have_executed`를 먼저 저장한다. 최초 정상 응답에만 유효기간 1.5초의 일회 실행권이 있다. 중복 응답·GET·영수증에는 실행권을 넣지 않는다.
5. 앱은 같은 foreground/restriction 세대와 같은 D/M을 다시 확인하고 `may_have_executed`, SDK 진입 횟수 1을 fsync한 뒤 SDK를 한 번 호출한다. 승인·기록 복구로 SDK 호출을 재구성하지 않는다.
6. `NAV_REPORT`는 실제 경로 두 번의 관측으로 applied/removed를 확인한다. 응답 지연·예외·프로세스 재시작으로 결과를 확정할 수 없으면 unknown으로 잠근다. SDK를 호출하기 전 중단한 로컬 기록은 not_dispatched로 보고한다. unknown을 제거 성공으로 취급하지 않는다. 실행 전 서버 승인만 남으면 `NAV_CANCEL`로 명시적으로 취소할 수 있다.

SDK가 순정 내비를 전면에 띄워 wayMate가 비활성화되어도 미완료 요청의 조회·결과 보고를 계속한다. 비활성 상태에서 새로운 승인·변경 호출은 하지 않는다. 관측 타임아웃은 다른 조회와 응답을 섞지 않도록 연결을 잠그며, 새 앱 연결이 필요하다.

## 좌표·소유권

소프트웨어드림센터 POI `36khp2hdj2cfcm5nqhe3`를 SDK `requestTrip`으로 독립 조회해 기준 좌표 37.41275833, 127.09481944의 30m 이내인지 확인한다. 이 조회는 경로를 변경하지 않는다. 조회 유효기간은 같은 SDK 세션의 10분이다.

현재 SDK의 경유지 응답에서 위경도가 0,0일 수 있다. raw 값은 그대로 보존하며 이름·POI ID·독립 조회 결과를 함께 검증한다. 다른 이름·ID·좌표·추가 경유지·변경된 D는 허용하지 않는다. 제거는 서버 소유권과 같은 차량의 로컬 추가 기록이 모두 있을 때 `FIRST` 한 개에만 실행한다. 전체 경유지 삭제 기능은 없다.

앱 기록 `files/navigation-journal-v1.json`과 기존 `files/navi-probe.json`은 보존한다. 예전 시험기에 미완료 시도나 소유 경유지가 있으면 새 연동을 잠근다. 병렬 SDK 작성자를 막기 위해 이전 debug 시험 Activity 진입은 비활성화했다. 서버 또는 앱 기록이 사라져 소유권을 증명할 수 없으면 새 서버·회차로 우회 실행하지 않는다. 결과 미확인 이후 수동 복구 UI와 일반 장소 검색은 후속이다.

## 실행

Node 22.22.2에서 `mock-app` 디렉터리:

```sh
WAYMATE_STATE_FILE=runtime/state-driver-navigation.json npm start
```

기본 `npm start`의 기존 `runtime/state-v3.json`은 그대로다. mock 앱과 real 앱의 기기 ID가 달라 기존 활성 여정을 옮길 수 없으므로 실제 연동 시연은 별도 파일을 사용한다. 기존 파일을 지우거나 활성 기기를 바꾸지 않는다. 순정 내비에서 목적지를 먼저 설정한 다음 real 앱에서 여행을 시작한다.

자동 검증은 `npm test` 및 차량 Gradle의 두 APK·두 lint·단위 테스트다. 실제 에뮬레이터 실행 증거와 범위는 별도 evidence 파일을 참고한다. 실제 주행 중 제한 전환이나 실차 환경까지 검증한 것은 아니다.
